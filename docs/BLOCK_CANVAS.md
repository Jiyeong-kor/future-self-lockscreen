# 블록 기반 연결 UX 설계

- 문서 상태: Draft v0.1
- 작성일: 2026-09-04
- 관련 문서: `docs/WHY_GRAPH.md`, `docs/SYNTHESIS_MODEL.md`, `docs/REFLECTION_MODEL.md`

## 1. 목적

Why Graph의 데이터 구조는 다대다 그래프이지만 사용자가 관계 타입과 그래프 이론을 이해해야 해서는 안 된다.

사용자에게는 스크래치처럼 **의미가 있는 블록을 끌어 서로 맞는 슬롯에 붙이면 연결이 만들어지는 방식**으로 보여준다.

핵심 원칙은 다음과 같다.

- 사용자는 선을 직접 그리고 관계 타입 이름을 외우지 않는다.
- 연결 가능한 대상에 가까이 가면 붙일 수 있는 슬롯이 나타난다.
- 잘못된 종류의 연결은 붙지 않는다.
- 연결되면 자연어 문장으로 관계를 확인한다.
- 그래프 구조는 내부에서 정확하게 저장한다.

## 2. 사용자에게 보이는 블록

각 도메인 요소를 카드형 블록으로 표현한다.

### 기록 블록

- CaptureEntry
- ReflectionItem
- SynthesisInsight

역할: 생각, 경험, 회고, 여러 기록에서 얻은 인사이트의 출처이다.

### 의미 블록

- Motive: 왜 중요한가
- Vision: 어떤 사람이거나 어떤 삶을 원하는가
- Goal: 어떤 결과를 만들고 싶은가
- Practice: 반복해서 무엇을 할 것인가
- Commitment: 어떤 기준으로 행동할 것인가

### 시간 기록

- OriginMoment
- MeaningCheckIn

이 둘은 일반 캔버스 블록으로 자유 연결하기보다 노드 또는 관계에 붙는 이력 카드로 표현한다.

## 3. 연결 슬롯

각 블록에는 아무 관계나 붙일 수 있는 범용 포트를 두지 않는다.

블록 종류에 따라 의미 있는 슬롯만 노출한다.

예시:

### Goal 블록

연결 슬롯:

- `왜?` → Motive
- `어떤 미래를 위해?` → Vision
- `어떤 기록에서 시작됐나?` → CaptureEntry, ReflectionItem, SynthesisInsight

### Practice 블록

연결 슬롯:

- `무엇을 위해?` → Goal
- `왜?` → Motive
- `어떤 기록에서 시작됐나?` → 출처 블록

### Commitment 블록

연결 슬롯:

- `왜 지키고 싶은가?` → Motive
- `어떤 목표를 돕는가?` → Goal
- `어떤 기록에서 시작됐나?` → 출처 블록
- `잠금화면에 보내기` → Lockscreen 출력

### Motive 블록

연결 슬롯:

- `어떤 미래와 연결되나?` → Vision
- `어디서 생긴 이유인가?` → 출처 블록

## 4. 드래그 앤 드롭 상호작용

### 4.1 기본 동작

1. 사용자가 블록을 길게 누른다.
2. 블록이 드래그 상태가 된다.
3. 다른 블록 근처로 이동하면 가능한 연결 슬롯만 강조된다.
4. 사용자가 원하는 슬롯 위에 놓는다.
5. 블록이 슬롯에 스냅된다.
6. 앱은 관계를 자연어로 확인한다.

예시:

```text
[돈 모으기] Goal을
[경제적 선택권] Motive의 연결 영역에 놓음

→ "돈 모으기를 하는 이유에 '경제적 선택권을 갖고 싶다'를 연결할까요?"
```

확인하면 내부적으로 다음을 생성한다.

```text
Goal --motivated_by--> Motive
```

### 4.2 잘못된 연결

잘못된 종류의 블록을 가져가면 슬롯이 나타나지 않는다.

예를 들어 ReflectionItem을 Practice의 `무엇을 위해?` 슬롯에 직접 붙일 수 없다.

대신 출처 슬롯에만 붙일 수 있다.

드롭이 불가능하면 블록은 원래 위치로 돌아간다.

### 4.3 햅틱과 애니메이션

- 유효한 슬롯 진입: 가벼운 햅틱
- 스냅 완료: 명확한 햅틱
- 잘못된 드롭: 짧은 되돌림 애니메이션

햅틱이 없어도 상태를 이해할 수 있도록 시각적 표현과 텍스트를 함께 사용한다.

## 5. 관계 자체도 보이는 객체로 취급한다

두 블록 사이의 관계는 단순한 선만 보여주지 않는다.

관계 중간에 짧은 의미 라벨을 표시할 수 있다.

예시:

```text
[돈 모으기]
   │
   ├─ 왜? ─→ [경제적 선택권]
   └─ 왜? ─→ [또래보다 뒤처지고 싶지 않음]
```

사용자가 `왜?` 라벨을 탭하면 해당 관계의 이력을 볼 수 있다.

- 언제 연결했는가
- 당시 왜 연결했는가
- 지금도 유효한가
- MeaningCheckIn 기록

따라서 관계도 사용자가 다시 생각하고 변경할 수 있는 1급 객체이다.

## 6. 관계 끊기

관계를 끊는다고 과거의 의미 이력을 삭제하지 않는다.

사용자는 다음 방식으로 현재 연결을 종료한다.

- 관계 라벨을 탭해 `연결 종료`
- 캔버스 편집 모드에서 관계를 `연결 해제` 영역으로 드래그

내부적으로 관계의 `validTo`를 기록하고 현재 관계에서만 제외한다.

완전 삭제는 별도 동작이다.

## 7. 여러 기록을 모아 인사이트 만들기

Synthesis 기능도 블록 상호작용과 연결한다.

### 7.1 `같이 보기` 영역

화면 하단 또는 별도 작업 공간에 `같이 보기` 영역을 제공한다.

사용자는 CaptureEntry, ReflectionItem, 기존 SynthesisInsight를 여러 개 끌어 이 영역에 놓을 수 있다.

예시:

```text
[아침 준비가 자꾸 늦는다]
[전날 옷을 꺼내면 편했다]
[일정 전날 준비하면 실수가 적었다]
                ↓ drag
          [같이 보기]
```

두 개 이상이 들어오면 `이 기록들을 함께 보니 어떤 생각이 드나요?` 입력이 활성화된다.

사용자가 작성한 결과는 새 SynthesisInsight 블록이 된다.

원본 블록들과는 SynthesisSourceLink로 연결한다.

### 7.2 상위 인사이트

여러 SynthesisInsight 블록을 다시 `같이 보기`에 넣어 상위 인사이트를 만들 수 있다.

Synthesis 간 순환은 허용하지 않는다.

## 8. P0 모바일 UX: Focus Board

첫 버전에서는 무한 캔버스를 만들지 않는다.

휴대전화 화면에서는 현재 선택한 한 블록을 중앙에 두는 `Focus Board`를 기본으로 사용한다.

예시:

```text
          [Vision 후보]

[Motive]  [돈 모으기 Goal]  [Motive]

          [Practice 후보]
```

하단에는 검색하거나 최근 사용한 블록을 보여주는 Block Tray가 있다.

사용자는 Tray의 블록을 중앙 카드 주변 슬롯으로 드래그한다.

장점:

- 작은 화면에서도 정확하게 드롭할 수 있다.
- 전체 그래프를 이해하지 않아도 된다.
- 관계 타입을 제한하기 쉽다.
- VoiceOver 대체 동작을 제공하기 쉽다.

## 9. P1 전체 캔버스: Meaning Map

P1에서는 전체 Why Graph를 자유롭게 탐색하는 캔버스를 제공한다.

기능:

- 확대와 축소
- 두 손가락 패닝
- 블록 위치 자유 배치
- 관계 라벨 표시
- 특정 블록 중심으로 포커스
- 연결된 경로만 강조
- 고립된 블록 확인
- 충돌 관계 표시
- 검색 결과로 해당 블록 이동

전체 캔버스에서도 연결 생성 규칙은 Focus Board와 동일하다.

## 10. 스크래치와 유사한 스냅 규칙

스크래치의 장점은 무엇이 어디에 붙을 수 있는지가 모양과 위치로 드러난다는 점이다.

이 앱에서도 비슷한 원칙을 사용한다.

- 이유 슬롯은 `왜?`
- 미래상 슬롯은 `어떤 미래?`
- 목표 슬롯은 `무엇을 위해?`
- 출처 슬롯은 `어디서 시작됐지?`

시각적 형태만으로 의미를 전달하지 않고 반드시 텍스트 라벨도 병행한다.

색상에만 의존하지 않는다.

## 11. 접근성 대체 흐름

드래그 앤 드롭은 유일한 연결 방법이 되어서는 안 된다.

모든 DnD 동작에는 동일한 결과를 만드는 탭 기반 흐름을 제공한다.

예시:

1. Goal 상세에서 `연결 추가` 선택
2. `왜 이 목표를 하나요?` 선택
3. Motive 목록에서 하나 이상 선택
4. 연결 확인

VoiceOver 사용자는 이 흐름만으로 전체 기능을 사용할 수 있어야 한다.

키보드, Switch Control 등 보조 입력도 고려한다.

## 12. Undo와 안전성

드래그 실수는 자주 발생할 수 있으므로 관계 생성과 종료 직후 Undo를 제공한다.

다음 동작은 즉시 영구 삭제하지 않는다.

- 관계 연결 해제
- 블록 이동
- 캔버스 위치 변경

의미 관계를 실제로 제거하는 동작에는 현재 연결만 종료할지 과거 기록까지 삭제할지 구분한다.

## 13. 충돌 관계

서로 상충하는 목표나 이유를 사용자가 직접 연결할 수도 있다.

예시:

- 돈을 최대한 모으고 싶다.
- 경험을 위해 지금 여행에 돈을 쓰고 싶다.

사용자는 두 블록을 선택해 `서로 충돌함` 관계를 만들 수 있다.

충돌은 오류가 아니다.

앱은 사용자가 상충하는 욕망을 동시에 가지고 있음을 보존하고 나중에 의미를 다시 검토할 수 있게 한다.

## 14. 구현 범위

### P0 데이터

- 모든 블록과 관계는 기존 Why Graph, Provenance, Synthesis 모델을 사용한다.
- UI 전용 위치 정보는 도메인 데이터와 분리한다.

```ts
export type CanvasPlacement = {
  id: string;
  canvasId: string;
  objectType: 'meaning_node' | 'capture_entry' | 'reflection_item' | 'synthesis_insight';
  objectId: string;
  x: number;
  y: number;
  updatedAt: string;
};
```

### P0 UI

- Focus Board
- Block Tray
- 길게 눌러 드래그
- 타입에 맞는 슬롯 노출
- 스냅 연결
- 연결 확인
- 관계 해제
- Undo
- 탭 기반 접근성 대체 흐름
- `같이 보기`에 여러 기록을 드래그해 Synthesis 생성

### P1

- 전체 Meaning Map 무한 캔버스
- 확대, 축소, 패닝
- 자동 레이아웃 보조
- 그래프 경로 강조
- 충돌, 고립 노드 탐색

## 15. 핵심 제품 원칙

> 내부는 그래프이지만 사용자가 그래프를 배워야 해서는 안 된다. 사용자는 생각 블록을 의미가 맞는 곳에 붙이는 것만으로 자신의 이유와 행동의 구조를 만들 수 있어야 한다.
