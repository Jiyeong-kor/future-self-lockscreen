# 개인 DB 연결과 암호화 키의 실패 처리

- 갱신일: 2026-09-24
- 제품 기준: PRD v1.2 및 DATA_LIFECYCLE_SECURITY.md
- 적용 범위: 기존 개인 DB 초기화, 공유 연결과 Keychain 어댑터
- 구현 위치: PR #1 작업 브랜치. main 반영 여부는 PR 상태를 확인한다.

## 구현 범위

이번 변경은 기존 DB 이름, 저장 경로, SQL 스키마, 암호화 키 서비스명과 기기별 키 접근 설정을 유지한다. 새 패키지, 결제, AI, 분석 SDK를 추가하지 않는다. 사용자의 기록을 분류하거나 행동 결정을 요구하는 UI도 추가하지 않는다.

### 키 읽기와 저장

키를 읽지 못한 오류와 키가 존재하지 않는 상태를 구분한다. Keychain 오류를 키 부재로 바꾸어 새 키로 대체하지 않는다. 읽은 값의 사용자명과 32바이트 소문자 16진수 형식을 검증한다. 기존 generateDatabaseEncryptionKey가 생성한 키 형식과 동일하다.

후보 키 생성과 확정은 저장소 인스턴스 안에서 직렬화한다. 동시에 여러 요청이 와도 후보를 한 번만 생성한다. 후보와 확정 키는 저장 후 다시 읽어 일치하는지 확인한다. 이미 확정된 다른 키는 덮어쓰지 않는다.

확정 키의 존재와 일치를 확인하기 전에는 후보 키를 제거하지 않는다. clearPending도 유일하게 남은 복구용 후보를 삭제하지 못한다. 명시적인 전체 데이터 초기화 기능은 이 API를 우회 사용하지 않고 별도 설계를 따라야 한다.

### DB 초기화

1. SQLCipher 지원 여부를 검사한다.
2. 확정 키 또는 기존 후보 키를 읽고 형식을 검사한다.
3. 해당 키로 연결을 열고 실제 스키마 페이지를 읽는다.
4. 기존 PRAGMA 설정과 migration을 실행한다.
5. 후보를 사용한 경우에만 키를 확정한다.
6. 초기화가 성공한 연결만 제공한다.

평문 DB로 대체하거나 기존 파일을 지워 재생성하는 복구는 수행하지 않는다. 키 접근 실패, 페이지 읽기 실패, 설정·migration 실패를 구분한다. 초기화가 실패하면 열린 연결을 닫는다. 연결 종료마저 실패한 경우에는 두 원인을 보존하고 같은 공유 세션에서 자동으로 새 핸들을 만들지 않는다.

### 공유 연결 수명

getPrivateDatabase는 원시 핸들 대신 해당 세션에 연결된 실행기를 제공한다. 동일 연결에 대한 일반 쿼리와 트랜잭션은 차례로 실행한다. 한 트랜잭션 중 외부 쿼리가 그 연결에 끼어들지 않도록 한다.

closePrivateDatabase는 새 작업을 거부한 다음, 이미 접수한 작업이 끝날 때까지 기다리고 원시 핸들을 닫는다. 종료 중 들어온 새로운 연결 요청은 종료 완료 뒤에 처리한다. 종료된 이전 실행기와 종료된 트랜잭션 실행기는 재사용하지 못한다.

공유 실행기의 동기 close 호출은 허용하지 않는다. 호출자는 closePrivateDatabase의 Promise를 기다려야 한다. 원시 SqlDatabase 인터페이스의 동기 close는 초기화 단계와 네이티브 어댑터의 내부 정리에만 사용한다.

같은 세션의 실행 순서를 기다리는 동안 트랜잭션 안에서 다시 getPrivateDatabase().execute 또는 closePrivateDatabase를 기다리지 않는다. 트랜잭션 콜백에서는 전달받은 transaction.execute만 사용해야 한다. 중첩 트랜잭션 API는 지원하지 않는다.

종료 실패 후에는 세션을 다시 열지 않으며 앱 프로세스를 다시 시작한 뒤 재검증해야 한다. 재시작은 데이터 삭제나 키 재생성을 뜻하지 않는다. 이 처리는 메모리 내 동일 세션의 경합에 관한 것이며 여러 프로세스 또는 여러 기기의 동시 쓰기를 해결하지 않는다.

## 자동 검증 범위

새 테스트 38개는 키 저장소, 암호화 DB 초기화 순서와 공유 연결 수명을 검증한다. 테스트 키는 실제 키가 아닌 공개 저장소용 가상 값이다. 저장·읽기·삭제 실패, 동시 후보 생성, 잘못된 키, migration 실패, 중복 종료, 종료 중 쓰기, 이전 실행기의 재사용과 초기화 실패 정리를 포함한다.

추가 테스트는 네이티브 API 대역을 사용한 로직 테스트다. 실제 SQLCipher 암호화, Keychain 권한과 잠금 전환을 검사하지 않는다. 기존 MeaningRepository의 실제 SQLite 통합 테스트도 유지하며 최종 전체 결과는 해당 PR 커밋의 CI 실행으로 판단한다.

로컬에서는 같은 테스트 본문을 TypeScript 변환 후 Node 22의 테스트 러너로 실행했다. 이것을 실제 Jest 전체 검사 또는 iOS 기기 테스트라고 표현하지 않는다. CI에서는 기존 Jest 설정으로 새 테스트와 기존 테스트를 함께 실행한다.

## 별도로 남은 네이티브 검증

이번 변경은 UIApplication의 protected data 알림과 closePrivateDatabase를 아직 연결하지 않는다. 따라서 잠금 버튼을 눌렀을 때 자동으로 DB를 닫는 기능이 완료된 상태는 아니다. JS 이벤트는 지연될 수 있으므로 OS 잠금 처리와 파일 보호는 별도 네이티브 검증이 필요하다.

DB, WAL, SHM, 검색 인덱스의 NSFileProtectionComplete 적용, 자동 백업 제외, 신규 파일과 기존 파일 전환, 재실행 후 데이터 유지, 잠금 중 접근 실패와 잠금 해제 후 복구를 실제 iOS 환경에서 확인해야 한다. 이번 변경으로 데이터 경로를 무조건 이동하거나 기존 DB를 삭제하지 않는다.

앱 전환기 가림, Face ID 앱 잠금, 파일 보호, SQLCipher는 서로 다른 보호 수단이다. 이번 연결 수명 테스트나 iOS 빌드 성공으로 이 모든 검증을 대신하지 않는다.
