# 구현 상태

- 갱신일: 2026-09-24
- 제품 기준: [PRD v1.2](PRD.md)
- 현재 단계: 빠른 기록과 의미 카드의 저장소 및 화면 연결
- 공개 배포 준비: 미완료

기능의 설계 확정, 코드 작성, 자동 테스트 통과, 네이티브 실기기 검증은 서로 다른 상태이다. 이 문서는 작성된 코드를 정식 제품 전체의 완료로 표현하지 않는다.

## 작성된 코드

| 영역 | 현재 범위 |
| --- | --- |
| 기반 | React Native 프로젝트, TypeScript 도메인 규칙, CI, SQLite 초기 스키마와 migration 실행기 |
| 개인 DB | OP-SQLite의 SQLCipher 설정, 보안 키 저장소 연동, 트랜잭션 어댑터. 기기 검증은 별도 필요 |
| 빠른 기록 | 본문 저장, 최초 revision 생성, 최근 기록 조회, 홈 입력과 기록 탭 |
| 의미 카드 | 분류 없이 생성, 불변 revision과 최초 기록 저장, 선택적 원본 기록 연결 |
| 출처 | 사용자가 선택한 CaptureEntry revision의 존재 확인과 카드 생성을 같은 트랜잭션에서 처리. 상세에서 최신 원문이 아니라 연결 당시 버전을 조회 |
| 검색 기반 | 새 의미 카드의 FTS 색인을 카드와 같은 트랜잭션에서 저장. 통합 검색 UI와 전체 색인 재구축은 아직 미구현 |
| 목록 | 의미 카드를 20개씩 조회. 생성 시각과 ID를 함께 사용하는 커서로 동일 시각의 카드도 페이지 경계에서 구분 |
| 작성 UI | 내용과 선택적 메모. 분류, 행동, 목표 입력 없음. 저장 실패 시 입력 유지, 저장 중 중복 요청 차단 |
| 기록 연결 UI | 기록의 더 보기 메뉴에서 사용자가 의미 카드로 남기기를 선택한 경우에만 작성 화면 표시. 원본을 이동하거나 삭제하지 않음 |
| 상세 UI | 카드의 전체 내용과 연결 당시의 원문 조회. 전체 Why Trail 기능은 아님 |

의미 카드의 기본 목록은 active와 paused를 대상으로 한다. 보관 및 종료 기록을 탐색하는 필터는 별도 구현 대상이다. 현재 카드 수정 UI가 없기 때문에 목록은 생성 시각 내림차순이다. 수정 기능을 추가할 때 IA의 정렬 옵션도 함께 구현한다.

## 이번 변경의 검증 범위

`src/repositories/__tests__/MeaningRepository.test.ts`는 Node 22의 실제 SQLite를 사용한다. SQL 문장 호출을 기록하기만 하는 테스트 대역으로 트랜잭션 성공을 판단하지 않는다.

검증 항목은 다음과 같다.

- 분류, 행동 원칙, 공개 문장 없이 의미 카드 생성
- 존재하지 않는 출처 거부와 부분 저장 방지
- 원문 수정 후에도 과거 출처 revision 유지
- 검색 색인 저장 실패 시 카드, 최초 기록, 출처 연결 롤백
- 동일 시각에 생성한 카드의 페이지 조회
- 현재 목록의 상태 필터
- 작성 화면에서 실패 후 입력 보존과 중복 저장 차단
- 작성 취소 시 미저장 내용 확인
- 사용자가 메뉴를 선택하기 전에는 의미 카드 작성 화면을 열지 않음
- 저장 성공 후 목록 조회 실패를 저장 실패로 오인하지 않음

화면 테스트는 React 렌더러와 저장소 대역을 사용한다. Node SQLite 테스트는 SQLCipher 암호화, iOS Keychain, 네이티브 모듈, 실제 터치 및 VoiceOver를 검증하지 않는다. 최종 자동 테스트 결과는 해당 커밋의 GitHub Actions 실행을 확인한다.

## 먼저 남아 있는 작업

### 네이티브 실행과 개인정보 보호

iOS 빌드와 실기기 실행을 검증해야 한다. SQLCipher 사용 여부, 재시작 후 데이터 복구, 키 접근 실패 처리, DB와 WAL·SHM의 파일 보호, 자동 백업 제외, 앱 전환기 가림, 키보드와 Safe Area, VoiceOver를 확인한다. 실기기 검증 전에는 가상 데이터로 개발한다.

### 기록과 의미의 편집

빠른 기록과 의미 카드의 수정은 새 revision으로 저장해야 한다. 분류 이벤트, 관계 생성, 전체 인과 그래프 검증, MeaningCheckIn, 갈등 검토와 Why Trail을 저장소 및 UI 수준에서 순서대로 연결한다. 이번 변경의 출처 검증은 새 의미 카드와 기존 빠른 기록 사이의 생성 경로에 한정한다. 모든 다형 참조의 삭제 및 복원 정합성까지 완료한 것은 아니다.

### 장기 데이터 조회

기록 탭은 아직 기존 getRecent(100)을 사용한다. 이는 제품의 데이터 개수 제한이 아니라 현재 조회 구현의 한계이며, 전체 기록용 페이지 조회로 교체해야 한다. 의미 목록용 인덱스와 대규모 데이터 성능, 전체 검색 UI, 기존 데이터의 색인 재구축, 삭제 시 색인 정리도 검증한다.

### 후속 기능

Synthesis, 블록 연결, 시간 여행, 잠금화면 승인과 WidgetKit 출력, 앱 잠금, 암호화 백업 및 복원, 내보내기와 멀티디바이스는 PRD와 단계별 구현 계획을 따른다. UI 문구나 기획 문서가 존재한다는 이유로 기능이 구현됐다고 판단하지 않는다.

### 의존성 보안

의존성 검사 결과는 일반 typecheck/test/lint 성공과 구분한다. 발견된 취약점은 직접 의존성과 전이 의존성, 실제 사용 경로, 수정 버전을 확인한 뒤 처리한다. 검사 통과를 위해 경고를 숨기거나 호환성을 검토하지 않은 강제 업데이트를 하지 않는다.

## 유지하는 제품 결정

현재 무료, 제품 내 AI 없음, 광고 및 데이터 판매 없음. 분류되지 않은 카드와 아무 행동으로 이어지지 않은 기록은 정상 상태이다. 사용자에게 분류, 행동 결정, 정체성 표현 변경, 주기적 의미 재확인을 요구하지 않는다.
