# Future Self 잠금화면 승인과 의미 재확인 정책

- 상태: 제품 안전 규칙
- 작성일: 2026-09-05
- 관련 문서: `docs/PRD.md`, `docs/DOMAIN_SCHEMA.md`, `docs/DATA_LIFECYCLE_SECURITY.md`

## 1. 핵심 원칙

Future Self는 다음 세 가지를 서로 다른 동작으로 취급한다.

1. 공개 문장의 내용 변경
2. 같은 공개 문장의 시각적 표현 변경
3. 사용자가 그 의미가 아직 중요하다고 다시 확인하는 것

이 세 가지를 하나의 `재승인` 개념으로 섞지 않는다.

## 2. 공개 승인

잠금화면은 주변 사람이 볼 수 있는 표면이므로 공개 문장의 내용이 달라지면 새 공개 승인이 필요하다.

다음은 새 `LockscreenProjectionRevision`을 만든다.

- `publicSafeMessage` 내용 변경
- `widgetMessage` 내용 변경
- `wallpaperMessage` 내용 변경

새 ProjectionRevision은 자동 승인되지 않는다.

사용자가 실제로 표시될 문구를 확인하고 승인한 뒤에만 잠금화면 후보가 될 수 있다.

기존 승인 문구는 사용자가 교체하거나 승인을 철회할 때까지 유지할 수 있다.

## 3. 시각적 스타일 변경

승인된 문장의 텍스트 내용이 동일하다면 다음 변경은 새 공개 승인을 요구하지 않는다.

- 배경 사진 변경
- 단색 배경 변경
- 글자 크기 변경
- 정렬 변경
- 문장 위치 변경
- 여백 변경
- 줄바꿈 변경
- 장식 또는 레이아웃 프리셋 변경

스타일 변경은 공개되는 의미 내용 자체를 바꾸지 않기 때문이다.

단, 스타일 처리 과정에서 텍스트 자체가 수정되면 새 ProjectionRevision과 승인이 필요하다.

## 4. 의미 재확인

사용자는 문장을 전혀 수정하지 않은 상태에서도 원하면 다음 의미를 기록할 수 있다.

`이 문장은 아직 나에게 중요하다.`

이 동작은 공개 승인과 무관하다.

의미 재확인은 `MeaningCheckIn(type='reaffirmed')` 같은 의미 이력으로 저장할 수 있다.

의미 재확인을 했다고 Projection 승인 상태가 바뀌지 않는다.

Projection을 승인했다고 MeaningCheckIn이 자동 생성되지도 않는다.

## 5. 의미 재확인은 선택 사항이다

Future Self는 의미 재확인을 사용자의 의무로 만들지 않는다.

금지하는 UX:

- `30일이 지났으니 다시 승인하세요`
- `계속 보려면 재확인하세요`
- 일정 기간마다 의미 재확인 강제
- 미확인 횟수나 기한 표시
- 재확인하지 않으면 잠금화면 문장을 자동 비활성화
- `아직 중요한가요?` 질문을 닫을 수 없는 모달로 표시

사용자는 같은 문장을 몇 달 또는 몇 년 동안 별도 재확인 없이 유지할 수 있다.

## 6. 익숙해짐에 대한 대응

잠금화면 문장이 익숙해져 눈에 잘 들어오지 않는 문제를 해결하기 위해 문장 변경을 강요하지 않는다.

사용자가 원할 때 다음 선택지를 제공할 수 있다.

- 같은 문장으로 배경 바꾸기
- 배치 바꾸기
- 표현을 새로 쓰기
- 다른 승인된 문장으로 바꾸기
- 의미를 다시 확인해 이력 남기기

문장 표현을 새로 쓰면 새 ProjectionRevision으로 취급하며 공개 승인을 다시 받는다.

스타일만 바꾸면 기존 승인 상태를 그대로 사용한다.

## 7. 제품 문구 원칙

공개 승인과 의미 재확인의 목적을 UI 문구에서도 구분한다.

공개 승인 의미:

`이 문장은 잠금화면에서 주변 사람에게 보일 수 있습니다.`

의미 재확인 의미:

`이 문장은 아직 나에게 중요해요.`

둘을 모두 `재승인`이라는 용어로 묶지 않는다.

## 8. 구현 불변조건

- 승인되지 않은 ProjectionRevision은 activeAnchor가 될 수 없다.
- 텍스트 내용 변경은 새 ProjectionRevision을 만든다.
- 새 ProjectionRevision에 이전 승인 이벤트를 승계하지 않는다.
- 스타일만 변경한 경우 텍스트 승인 revision을 새로 만들지 않는다.
- MeaningCheckIn reaffirmed는 ProjectionApprovalEvent와 별개이다.
- 의미 재확인은 자동 생성하거나 주기적으로 강제하지 않는다.
- 공개 승인 철회와 의미의 중요성 감소 역시 별개로 처리한다.

## 9. 핵심 문장

> 승인은 개인정보 보호를 위한 안전장치이고, 재확인은 사용자가 원할 때 남기는 의미 이력이다. 둘은 서로 대체하지 않으며 어느 쪽도 다른 쪽을 자동으로 발생시키지 않는다.
