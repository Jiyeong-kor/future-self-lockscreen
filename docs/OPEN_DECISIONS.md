# Future Self Lockscreen 제품 결정 검토

PRD v0.2에서 구현 전에 사용자 확인이 필요한 제품 결정을 분리한 문서이다.

## D-01. 1차 대상 플랫폼

- A. iOS 우선
- B. Android 우선
- C. 두 플랫폼 동시

권장: A. iOS에서 핵심 반복 노출 경험을 먼저 완성한 뒤 Android 직접 배경화면 적용을 추가한다.

## D-02. iOS WidgetKit의 MVP 포함 여부

- A. 이미지 생성만 MVP
- B. 이미지 생성 + 잠금화면 WidgetKit까지 MVP

권장: B. 이미지 생성만 제공하면 메시지 변경 시 사용자가 배경화면을 다시 적용해야 하므로 제품의 핵심인 지속 노출이 약해진다.

## D-03. 여러 메시지가 동시에 활성화될 때의 행동

- A. 가장 중요한 메시지 하나만 표시
- B. 일정 주기로 자동 회전
- C. 여러 개를 순서대로 표시

권장: A. MVP에서는 결정론적으로 하나만 선택한다.

## D-04. 기본 노출 기간

사용자가 노출 기간을 지정하지 않았을 때의 기본 정책이다.

- A. 체크포인트 월 전체
- B. 체크포인트 30일 전부터
- C. 항상 표시
- D. 반드시 사용자가 지정

권장: 월 체크포인트는 해당 월 전체, 특정 날짜는 30일 전부터 해당 날짜까지.

## D-05. 체크포인트까지 남은 기간 표시

- A. 홈과 잠금화면 모두 표시
- B. 홈에서만 표시
- C. 표시하지 않음

권장: MVP에서는 홈에 표시하고 잠금화면 표시는 사용자 선택 기능으로 후속 추가한다.

## D-06. 데이터 백업 정책

- A. OS 기본 백업 허용
- B. 앱 데이터 자동 백업 제외 + 수동 내보내기 제공

권장: B. 개인적인 후회와 목표 문장을 다루므로 자동 클라우드 백업을 기본 동작으로 두지 않는다.

주의: 사용자가 생성 이미지를 사진 보관함에 저장하면 해당 이미지는 iCloud Photos 또는 사용자가 사용하는 사진 동기화 정책의 영향을 받을 수 있다. 앱 내부 데이터 백업 정책과 사진 보관함 동기화는 별개의 문제이다.

## D-07. React Native 프로젝트 형태

- A. React Native Community CLI
- B. Expo 기반

권장: A. iOS Widget Extension과 Android Kotlin 네이티브 모듈을 직접 다뤄야 하기 때문이다.

## D-08. 초기 공개 범위

- A. 본인 사용 전용 MVP로 빠르게 완성
- B. 처음부터 App Store와 Play Store 공개 품질을 목표

권장: A로 시작하되 도메인 모델과 화면 문구는 특정 개인이나 편입 시험에 종속하지 않는다.

## D-09. 문장 작성 방식

- A. 사용자가 모든 문장을 자유 입력
- B. 질문형 입력 가이드 + 사용자 직접 작성
- C. AI가 문장을 생성하거나 재작성

권장: B. 제품의 핵심 콘텐츠가 사용자의 실제 경험이라는 원칙을 유지한다.

## D-10. 실제 앱 표시 이름

저장소 이름 `future-self-lockscreen`과 앱스토어 또는 홈 화면에 표시할 제품명은 별도로 결정한다.

후보 방향:

- Future Self
- Future Self Lockscreen
- 다시 후회하지 않기
- 미래의 나에게
- 별도 한국어 이름

권장: 구현용 저장소 이름은 유지하고, 실제 표시 이름은 UI 디자인을 시작하기 전에 별도로 확정한다.

## D-11. 잠금화면 배경 소스

잠금화면 이미지 생성 시 어떤 배경을 1차 지원할지 결정한다.

- A. 단색 배경만
- B. 사용자가 사진 보관함에서 선택한 이미지 + 단색 배경
- C. 앱이 현재 기기의 잠금화면 배경을 자동으로 읽어서 재사용

권장: B.

C는 기본 제품 요구사항으로 두지 않는다. iOS 일반 앱에서 현재 잠금화면 배경을 자유롭게 읽고 다시 설정하는 흐름을 전제로 설계하기 어렵고, Android에서도 현재 배경화면 읽기는 권한과 플랫폼 제약이 크다. 사용자가 기존 배경과 같은 이미지를 쓰고 싶다면 사진 보관함에서 원본 이미지를 다시 선택하는 흐름을 제공한다.
