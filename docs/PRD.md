## 0. 문서 목적

이 문서는 Future Self Lockscreen의 제품 목적, 사용자 경험, 기능 요구사항, 데이터 구조, 플랫폼 제약, 구현 우선순위와 아직 확정하지 않은 제품 결정을 정의한다.

이 앱의 목표는 단순히 문구가 들어간 배경화면을 만드는 것이 아니다. 사용자가 과거 특정 시점에 반복했던 후회를 미래의 경고 신호로 저장하고, 현재의 행동 원칙과 연결한 뒤, 잠금화면이라는 반복 노출 지점에서 계속 확인하도록 만드는 것이 핵심이다.

---

## 1. 제품 한 줄 정의

과거의 반복된 후회를 미래의 체크포인트로 바꾸고, 같은 후회를 다시 하지 않기 위해 지금 해야 할 말을 잠금화면에서 반복적으로 보여주는 개인 행동 리마인더 앱이다.

## 2. 제품 배경

사용자는 매년 특정 시기가 되면 과거에 하지 않은 선택을 떠올리며 후회할 수 있다.

대표적인 초기 사례는 다음과 같다.

- 시기: 12월
- 반복된 생각: “수능을 봤어야 했는데.”
- 현재 발견한 의미: 대학 편입을 반드시 끝내야 하는 개인적인 이유 중 하나가 이 반복된 후회와 연결되어 있다.
- 현재 행동으로의 변환: “다음 12월에도 같은 후회를 하고 싶지 않다면 지금 편입 준비를 해야 한다.”

기존 메모, 명언, 할 일 앱은 각각 기록, 감정 자극, 실행 관리에는 강하지만, “과거의 후회 → 미래에 다시 맞이할 시점 → 현재 행동”이라는 시간 구조를 한 화면에서 계속 상기시키지는 않는다.

Future Self Lockscreen은 이 연결을 제품의 핵심 모델로 삼는다.

## 3. 해결하려는 문제

### 3.1 핵심 문제

사용자는 장기 목표의 중요성을 알고 있어도 일상에서는 미래의 결과를 체감하기 어렵다. 시간이 충분히 지나고 특정 시기가 다시 돌아온 뒤에야 “그때 했어야 했다”는 후회를 강하게 느낀다.

문제는 후회 자체가 아니라, 후회가 현재의 구체적인 판단 기준으로 지속되지 않는다는 점이다.

### 3.2 기존 방식의 한계

- 메모 앱은 사용자가 직접 열어야 하므로 반복 노출이 약하다.
- 일반 알림은 확인하면 사라지고 맥락이 단절된다.
- 명언 앱은 사용자의 실제 경험과 연결되지 않는다.
- 일반 할 일 앱은 무엇을 해야 하는지는 알려주지만 왜 해야 하는지는 계속 보여주지 않는다.
- 고정 배경화면 문구는 쉽게 만들 수 있지만 시기별 메시지 관리, 우선순위, 수정, 자동 선택이 어렵다.

## 4. 핵심 가치 제안

제품은 다음 세 요소를 항상 연결한다.

1. **과거**: 내가 무엇을 후회했는가
2. **미래**: 어느 시점에 같은 후회를 다시 하게 될 가능성이 있는가
3. **현재**: 그 미래를 피하려면 지금 어떤 원칙으로 행동해야 하는가

잠금화면에 노출되는 메시지는 이 세 요소 중 현재 행동에 필요한 부분만 짧게 보여준다. 전체 맥락은 앱 내부에서 확인할 수 있다.

## 5. 대상 사용자

### 5.1 1차 사용자

- 특정 시기마다 비슷한 후회를 반복하는 사람
- 장기 목표가 있지만 일상에서 목표의 이유를 자주 잊는 사람
- 일반적인 동기부여 문구보다 자신의 실제 경험에서 나온 문장을 더 중요하게 느끼는 사람
- 휴대전화를 자주 확인하므로 잠금화면 반복 노출이 효과적인 사람

### 5.2 초기 제품 범위

초기 버전은 개인 사용을 우선한다. 다만 데이터 구조와 화면 구조는 추후 일반 사용자에게 배포할 수 있도록 특정 시험이나 편입에 종속하지 않는다.

### JTBD-02

“휴대전화를 열 때마다 지금 가장 중요한 메시지를 보고, 당장의 행동이 장기 목표와 연결되어 있다는 점을 떠올리고 싶다.”

### JTBD-03

“여러 후회와 목표가 있어도 지금 시점에 가장 중요한 메시지만 자동으로 선택되게 하고 싶다.”

## 7. 제품 목표

1. 사용자가 과거의 후회를 구체적인 문장으로 저장할 수 있어야 한다.
2. 사용자가 후회와 연결된 미래 체크포인트를 지정할 수 있어야 한다.
3. 사용자가 같은 후회를 피하기 위해 현재의 자신에게 하는 말을 작성할 수 있어야 한다.
4. 앱은 날짜, 사용자가 지정한 노출 규칙, 우선순위를 기준으로 현재 메시지를 결정해야 한다.
5. 사용자는 앱을 직접 열지 않아도 잠금화면에서 핵심 메시지를 볼 수 있어야 한다.
6. 사용자가 메시지를 수정하면 잠금화면용 콘텐츠에도 쉽게 반영할 수 있어야 한다.
7. 핵심 기능은 서버 없이 동작해야 한다.

## 8. 비목표

MVP에서는 다음 기능을 목표로 하지 않는다.

- SNS 또는 커뮤니티
- 다른 사용자가 작성한 명언 피드
- 감정 진단 또는 심리 평가
- AI가 사용자를 대신하여 공격적인 동기부여 문장을 생성하는 기능
- 복잡한 습관 추적, 연속 기록, 점수화
- 일정 관리 앱이나 할 일 앱 전체를 대체하는 기능
- 광고 또는 수익화
- 필수 계정 가입
- 서버 기반 소셜 동기화

## 9. 핵심 용어

### 9.1 후회 항목 `RegretEntry`

한 번의 후회 경험과 그 후회에서 도출한 현재 메시지를 묶은 단위이다.

### 9.2 미래 체크포인트 `Checkpoint`

사용자가 같은 후회를 다시 경험하고 싶지 않은 미래 시점이다.

예시:

- 매년 12월
- 매년 11월 15일부터 12월 31일까지
- 2027년 1월 편입 시험 결과 확인 시점

### 9.3 노출 기간 `DisplayWindow`

해당 메시지를 잠금화면 후보로 활성화할 기간이다. 미래 체크포인트와 반드시 동일하지는 않다.

예를 들어 후회의 체크포인트가 12월이라도 메시지는 9월부터 12월까지 보여줄 수 있다.

### 9.4 현재 메시지 `ActiveMessage`

현재 시점에 앱이 가장 우선적으로 보여주기로 선택한 후회 항목의 메시지이다.

### 9.5 고정 `Pin`

자동 선택 규칙을 일시적으로 무시하고 사용자가 특정 메시지를 최우선으로 표시하는 기능이다.

## 10. 핵심 사용자 흐름

### 10.1 첫 사용

1. 사용자가 앱을 실행한다.
2. 앱은 제품 목적을 짧게 설명한다.
3. 사용자는 샘플 데이터를 사용하지 않고 자신의 첫 후회 항목을 작성하거나 온보딩을 건너뛸 수 있다.
4. 사용자는 과거의 후회, 미래 체크포인트, 현재의 자신에게 하는 말, 행동 원칙을 입력한다.
5. 앱은 저장한 내용을 기반으로 현재 메시지 미리보기를 보여준다.
6. 사용자는 잠금화면용 콘텐츠를 만든다.

### 10.2 후회 등록

예시 입력:

- 제목: 12월의 수능 후회
- 과거의 후회: 올해도 수능을 준비하지 않았다는 생각을 했다.
- 미래 체크포인트: 매년 12월
- 노출 기간: 9월 1일 ~ 12월 31일, 매년 반복
- 현재의 나에게 하는 말: 내년 12월에도 같은 생각을 하고 싶지 않으면 지금 편입 공부를 해야 한다.
- 행동 원칙: 편입 준비를 미루지 않는다.
- 잠금화면 강조 문장: 다음 12월의 내가 후회하지 않게 오늘 공부한다.

### 10.3 현재 메시지 확인

1. 앱은 현재 활성화된 항목을 계산한다.
2. 사용자가 고정한 항목이 있으면 해당 항목을 우선한다.
3. 고정 항목이 없으면 노출 기간과 우선순위를 기준으로 현재 메시지를 선택한다.
4. 홈에서는 현재 메시지와 그 메시지가 선택된 이유를 보여준다.

예시:

- “현재 노출 기간에 포함되어 있습니다.”
- “사용자가 직접 고정했습니다.”

### 10.4 잠금화면 반영

#### iOS

- 앱은 잠금화면용 이미지를 생성하고 사진 보관함에 저장할 수 있다.
- 사용자는 iOS 배경화면 설정 흐름에서 이미지를 직접 적용한다.
- 잠금화면에 지속적으로 짧은 메시지를 노출하려면 WidgetKit 기반 잠금화면 위젯을 제공한다.

Apple은 iPhone 잠금화면에서 `accessoryRectangular`, `accessoryInline`, `accessoryCircular` WidgetKit 패밀리를 지원한다.

참고:
- https://developer.apple.com/documentation/widgetkit/widgetfamily/accessoryrectangular
- https://developer.apple.com/documentation/widgetkit/creating-accessory-widgets-and-watch-complications

#### Android

- 앱은 잠금화면용 이미지를 생성한다.
- 지원 가능한 기기에서는 Android 네이티브 모듈을 통해 잠금화면 전용 배경으로 직접 적용한다.
- `WallpaperManager.FLAG_LOCK`과 `SET_WALLPAPER` 권한을 사용한다.

참고:
- https://developer.android.com/reference/android/app/WallpaperManager

## 12. 상세 기능 요구사항

### FR-01. 후회 항목 생성

사용자는 다음 필드를 입력할 수 있어야 한다.

필수:

- 제목
- 과거의 후회
- 현재의 자신에게 하는 말
- 미래 체크포인트

선택:

- 행동 원칙
- 잠금화면 강조 문장
- 노출 기간
- 우선순위
- 메모

검증 규칙:

- 제목은 공백만 입력할 수 없다.
- 현재의 자신에게 하는 말은 공백만 입력할 수 없다.
- 시작일이 종료일보다 늦을 수 없다.
- 반복 기간이 연도를 넘어가는 경우를 허용해야 한다. 예: 매년 11월 1일 ~ 다음 해 1월 15일.

### FR-02. 후회 항목 수정

사용자는 모든 사용자 입력 필드를 수정할 수 있어야 한다.

수정 직후 현재 메시지 선택 조건이 바뀌면 홈 화면에 즉시 반영해야 한다.

### FR-03. 삭제와 보관

사용자는 항목을 삭제하거나 보관할 수 있어야 한다.

- 삭제: 데이터에서 제거한다.
- 보관: 기록은 유지하지만 자동 노출 후보에서 제외한다.

삭제 전에는 확인 절차를 제공한다.

### FR-04. 미래 체크포인트

지원 모드:

1. 특정 날짜 1회
2. 매년 특정 월
3. 매년 특정 월/일
4. 매년 날짜 범위

MVP에서 반복 규칙을 데이터 모델에 포함한다. 반복 규칙을 나중에 추가하면 기존 `targetMonths` 구조를 마이그레이션해야 하기 때문이다.

### FR-05. 노출 기간

사용자는 미래 체크포인트와 별도로 메시지 노출 기간을 정할 수 있어야 한다.

지원 모드:

- 항상
- 특정 날짜 범위 1회
- 매년 반복 날짜 범위

노출 기간을 입력하지 않으면 기본 정책을 적용한다.

기본 정책은 사용자 결정 전까지 다음 안을 사용한다.

- 체크포인트가 월 단위이면 해당 월 전체
- 체크포인트가 날짜이면 체크포인트 30일 전부터 해당 날짜까지

이 기본 정책은 **사용자 검토 필요** 상태이다.

### FR-06. 현재 메시지 선택

현재 메시지 선택기는 결정론적으로 동작해야 한다. 앱을 열 때마다 이유 없이 다른 문장이 선택되면 안 된다.

우선순위 초안:

1. 사용자가 수동으로 고정한 활성 항목
2. 현재 날짜가 노출 기간에 포함되는 항목 중 가장 높은 사용자 우선순위
3. 우선순위가 같으면 체크포인트가 더 가까운 항목
4. 그래도 같으면 최근 수정한 항목
5. 활성 항목이 없으면 기본 메시지 또는 빈 상태

여러 항목을 무작위로 회전시키는 기능은 MVP에 포함하지 않는다.

### FR-07. 고정

- 사용자는 한 번에 하나의 항목만 고정할 수 있다.
- 다른 항목을 고정하면 기존 고정은 해제된다.
- 고정 해제 시 자동 선택 규칙으로 즉시 복귀한다.

### FR-08. 홈

홈은 앱을 열었을 때 가장 먼저 “지금 봐야 할 말”을 보여준다.

필수 요소:

- 잠금화면 강조 문장
- 현재의 자신에게 하는 말
- 연결된 후회 제목
- 현재 메시지가 선택된 이유
- 미래 체크포인트
- 잠금화면 만들기 또는 업데이트 버튼
- 편집 버튼

선택 요소:

- 체크포인트까지 남은 일수

### FR-09. 잠금화면 편집기

사용자는 다음 항목을 조정할 수 있어야 한다.

- 표시할 텍스트
- 글자 크기
- 글자 굵기
- 정렬
- 수평 위치
- 수직 위치
- 최대 줄 수
- 배경 이미지
- 단색 배경
- 밝은 글자 또는 어두운 글자
- 텍스트 영역의 대비 보조 효과

미리보기는 실제 OS 잠금화면의 시계, 알림, 사용자별 확대·크롭을 완벽하게 재현한다고 표현해서는 안 된다. 기기와 OS 설정에 따라 실제 결과가 달라질 수 있기 때문이다.

### FR-10. 이미지 생성

앱은 기기 화면 비율과 해상도를 기준으로 잠금화면용 정적 이미지를 생성할 수 있어야 한다.

요구사항:

- 화면 비율 유지
- 텍스트 잘림 방지
- 사용자 선택 배경 유지
- 이미지 저장 전 최종 미리보기
- 생성 실패 시 원인 메시지 표시

### FR-11. iOS WidgetKit

WidgetKit을 MVP에 포함하기로 결정하면 다음 요구사항을 적용한다.

- `accessoryRectangular`을 1차 지원한다.
- 긴 본문이 아니라 잠금화면 강조 문장을 표시한다.
- 위젯 탭 시 해당 후회 항목 상세 화면으로 이동한다.
- React Native 앱과 Widget Extension은 App Group 공유 저장소를 통해 필요한 최소 데이터만 공유한다.
- 위젯은 전체 후회 원문을 복제하지 않고 표시용 메시지와 식별자만 공유하는 방향을 우선한다.

추후 `accessoryInline` 지원을 검토한다.

### FR-12. Android 잠금화면 적용

- Kotlin 네이티브 모듈에서 `WallpaperManager`를 사용한다.
- 지원 여부를 `isWallpaperSupported()`와 `isSetWallpaperAllowed()`로 확인한다.
- `FLAG_LOCK`을 사용하여 잠금화면 전용 적용을 시도한다.
- 적용 실패 시 사용자가 직접 설정할 수 있도록 생성 이미지를 저장하는 대체 경로를 제공한다.

### FR-13. 메시지 변경 알림

알림은 기본적으로 선택 기능이다.

알림 발생 후보:

- 새로운 노출 기간이 시작됨
- 고정된 메시지의 체크포인트가 임박함
- 현재 잠금화면 이미지와 앱의 현재 메시지가 달라짐

MVP에서는 과도한 반복 알림을 만들지 않는다.

### FR-14. 로컬 저장

- 핵심 데이터는 서버 없이 저장한다.
- 네트워크가 없어도 생성, 수정, 조회, 이미지 생성이 가능해야 한다.
- 로그에 사용자의 후회 원문과 메시지 본문을 기록하지 않는다.

### FR-15. 데이터 내보내기와 가져오기

P1에서 JSON 기반 내보내기와 가져오기를 지원한다.

목적:

- 서버 계정 없이 기기 교체에 대응
- 사용자가 자신의 기록을 소유할 수 있게 함

### FR-16. 앱 잠금

P1에서 Face ID, Touch ID 또는 Android 생체 인증 기반 앱 잠금을 검토한다.

잠금화면 위젯에 표시되는 문장은 기기 잠금 상태에서도 보일 수 있으므로, 위젯에 어떤 문장을 노출할지는 사용자 스스로 결정한다.

## 15. 현재 메시지 선택 규칙

### 15.1 기본 알고리즘

```text
1. 보관된 항목을 제외한다.
2. 고정된 항목이 있으면 고정 항목을 반환한다.
3. 현재 날짜가 노출 기간에 포함되는 항목만 남긴다.
4. priority가 높은 항목을 우선한다.
5. priority가 같으면 다음 체크포인트가 가까운 항목을 우선한다.
6. 그래도 같으면 updatedAt이 최근인 항목을 우선한다.
7. 후보가 없으면 빈 상태를 반환한다.
```

### 15.2 결정론 원칙

같은 데이터와 같은 날짜에서는 항상 같은 항목을 선택한다.

무작위 메시지 회전은 사용자가 의도한 가장 중요한 메시지를 가릴 수 있으므로 MVP에서는 사용하지 않는다.

## 16. 기술 방향

### 16.1 React Native

2026-09-03 기준 React Native 0.87.x가 안정 릴리스이다. 구현 시작 시점에는 최신 안정 패치 버전을 확인한 뒤 버전을 고정한다.

참고:
- https://reactnative.dev/releases/

기본 방향:

- React Native Community CLI
- TypeScript
- React Navigation
- 공통 비즈니스 로직은 TypeScript로 유지
- OS 전용 기능만 Swift/Kotlin으로 분리

### 16.2 Expo 사용 여부

현재 제품은 Widget Extension과 Android 네이티브 모듈이 핵심에 들어갈 가능성이 높다. 따라서 Expo Managed Workflow보다는 React Native Community CLI 기반 구성을 기본안으로 권장한다.

이 결정은 **사용자 검토 필요** 상태이다.

### 16.3 로컬 저장

MVP에서는 데이터 규모가 작고 복잡한 관계형 쿼리가 필요하지 않으므로 단순 로컬 저장소로 시작할 수 있다.

요구사항:

- 데이터 스키마 버전 관리
- 향후 마이그레이션 가능 구조
- 사용자 원문 로그 금지

구체 라이브러리는 구현 시작 시 최신 유지보수 상태를 확인해 결정한다.

### 16.4 이미지 렌더링

잠금화면 미리보기 UI와 실제 생성 이미지의 결과가 가능한 한 일치해야 한다.

이미지 생성 방식은 구현 Spike에서 다음을 검증한다.

- React Native View 캡처
- 네이티브 렌더링 필요 여부
- 고해상도 출력 시 텍스트 품질

### 16.5 iOS 네이티브 경계

Swift / SwiftUI / WidgetKit이 담당한다.

- Widget Extension
- App Group 공유 데이터
- 위젯 Timeline 갱신
- 딥링크 또는 App Intent 연결

React Native가 전체 후회 목록과 편집 UI를 담당한다.

### 16.6 Android 네이티브 경계

Kotlin이 담당한다.

- WallpaperManager 연동
- 잠금화면 적용 가능 여부 확인
- 이미지 전달과 적용 결과 반환

## 17. 플랫폼 제약

### 17.1 iOS

일반 앱의 핵심 경로는 다음 두 가지로 분리한다.

1. 정적 잠금화면 이미지 생성 후 사용자가 직접 배경화면으로 적용
2. WidgetKit 잠금화면 위젯으로 짧은 메시지 지속 노출

iOS 이미지 생성 기능을 “자동 배경화면 변경”이라고 표현하지 않는다.

Apple의 일반 사용자용 공식 안내 역시 사진을 선택한 뒤 “Use as Wallpaper”로 적용하는 흐름을 사용한다.

참고:
- https://developer.apple.com/wwdc26/wallpaper/

### 17.2 Android

`WallpaperManager.FLAG_LOCK`은 API 24부터 잠금화면 전용 배경을 지정하는 플래그로 제공된다.

기기 정책이나 제조사 구현에 따라 설정이 허용되지 않을 수 있으므로 런타임 검사를 수행한다.

### 21.1 MVP 완료 기준

1. 사용자가 후회 항목을 생성, 수정, 보관, 삭제할 수 있다.
2. 1회 또는 매년 반복 체크포인트를 저장할 수 있다.
3. 노출 기간을 저장할 수 있다.
4. 같은 날짜와 같은 데이터에서는 같은 현재 메시지가 선택된다.
5. 사용자가 현재 메시지를 수동 고정할 수 있다.
6. 잠금화면 이미지를 생성하고 실제 기기에 적용할 수 있다.
7. 앱을 종료하고 다시 실행해도 데이터가 유지된다.
8. 네트워크 연결 없이 핵심 기능을 사용할 수 있다.
9. 사용자 원문이 로그나 외부 서버로 전송되지 않는다.

### 21.2 제품 성공 신호

MVP 이후 다음을 관찰할 수 있다.

- 사용자가 실제 잠금화면에 메시지를 유지하는가
- 사용자가 한 번 작성한 항목을 나중에 다시 수정하는가
- 여러 후회 항목을 생성하는가
- 사용자가 “지금 왜 이 행동을 해야 하는지 떠올리는 데 도움이 되었다”고 느끼는가

초기 개인용 버전에서는 외부 분석 SDK 대신 직접 사용 기록과 사용자 피드백으로 검증한다.

## 24. 사용자 검토가 필요한 결정

다음 항목은 구현 전에 사용자에게 확정받아야 한다.

### D-01. 1차 대상 플랫폼

선택지:

- A. iOS 우선
- B. Android 우선
- C. 두 플랫폼 동시

**권장: iOS 우선, Android 후속.** 잠금화면 반복 노출이라는 핵심 경험을 먼저 한 기기에서 완성한 뒤 Android 직접 적용을 추가하는 편이 범위를 통제하기 쉽다.

### D-02. iOS WidgetKit을 첫 MVP에 포함할지

선택지:

- A. 이미지 생성만 MVP
- B. 이미지 생성 + 잠금화면 WidgetKit까지 MVP

**권장: B.** 이미지 생성만으로는 메시지 변경 때 사용자가 매번 배경화면을 다시 적용해야 하므로 핵심 가치인 반복 노출과 자동 선택이 느슨하게 연결된다.

### D-03. 메시지가 여러 개 활성화되었을 때의 행동

선택지:

- A. 가장 중요한 메시지 하나만 표시
- B. 일정 주기로 자동 회전
- C. 사용자가 여러 개를 순서대로 선택

**권장: A.** MVP에서는 가장 중요한 메시지 하나만 결정론적으로 보여준다.

### D-04. 기본 노출 기간

사용자가 노출 기간을 직접 지정하지 않았을 때의 기본값이다.

선택지:

- A. 체크포인트 월 전체
- B. 체크포인트 30일 전부터
- C. 항상 표시
- D. 기본값 없이 반드시 직접 설정

**권장: 체크포인트 종류에 따라 월은 해당 월 전체, 특정 날짜는 30일 전부터.**

### D-05. 체크포인트까지 남은 날짜 표시

예시: `12월까지 89일`, `편입 원서 마감까지 D-27`

선택지:

- A. 홈과 잠금화면 모두 표시
- B. 홈에서만 표시
- C. 표시하지 않음

**권장: 홈에서는 P0, 잠금화면에서는 P1 또는 사용자 선택.** 잠금화면 메시지가 너무 많은 정보로 복잡해지는 것을 막는다.

### D-06. 데이터 백업

선택지:

- A. OS 기본 백업 허용
- B. 자동 백업 제외 + 수동 내보내기

**권장: B.** 개인적인 후회 원문을 다루므로 기본 동작을 보수적으로 둔다.

### D-07. 프로젝트 형태

선택지:

- A. React Native Community CLI
- B. Expo 기반

**권장: A.** Widget Extension과 Android 네이티브 모듈의 비중이 크기 때문이다.

### D-08. 제품의 초기 공개 범위

선택지:

- A. 본인 사용 전용으로 빠르게 완성
- B. 처음부터 App Store/Play Store 공개 품질을 목표

**권장: A로 시작하되 데이터와 화면은 일반화한다.** 실제 사용에서 핵심 경험을 먼저 검증한 다음 공개 배포 요구사항을 추가한다.

### D-09. 앱 내 문장 작성 방식

선택지:

- A. 사용자가 전부 직접 작성
- B. 질문형 입력 가이드만 제공
- C. AI가 문장을 생성하거나 재작성

**권장: B.** 핵심 콘텐츠의 주체는 사용자로 유지하면서도 “과거 → 미래 → 현재” 구조를 작성하기 쉽게 만든다. AI 생성은 MVP에서 제외한다.

## 25. 현재 권장 결정안

사용자가 별도로 변경하지 않는다면 다음 조합이 제품의 목적과 구현 비용의 균형이 가장 좋다.

- iOS 우선
- React Native Community CLI + TypeScript
- iOS WidgetKit `accessoryRectangular`을 MVP에 포함
- 잠금화면 이미지 생성도 함께 제공
- 가장 중요한 메시지 하나만 자동 선택
- 매년 반복 체크포인트와 노출 기간을 처음부터 데이터 모델에 포함
- 질문형 작성 가이드를 제공하되 AI 생성은 제외
- 서버, 광고, 분석 SDK 없음
- 자동 클라우드 백업 제외
- P1에서 수동 JSON 내보내기/가져오기와 Android 직접 잠금화면 적용 추가
