# Future Self 복귀와 재노출 안전 정책

- 상태: 제품 경험 규칙
- 작성일: 2026-09-05
- 관련 문서: `docs/PRD.md`, `docs/DATA_LIFECYCLE_SECURITY.md`, `docs/RED_TEAM_PRODUCT_STRATEGY_V1.md`

## 1. 핵심 원칙

Future Self는 사용자가 오래 앱을 사용하지 않았다는 사실을 실패로 취급하지 않는다.

사용자는 매일, 매주 또는 매달 앱을 열 의무가 없다.

앱의 목적은 사용 빈도를 유지시키는 것이 아니라 사용자가 필요할 때 과거의 생각과 의미를 다시 이해할 수 있게 하는 것이다.

따라서 복귀 경험의 원칙은 다음 문장으로 정의한다.

> 오랜만에 돌아온 사용자를 밀린 기록과 검토 과제로 맞이하지 않고, 원하면 이전의 중요한 맥락을 짧게 복구할 수 있게 한다.

또한 재노출 정책은 다음 문장을 따른다.

> Future Self는 사용자가 다시 볼 준비가 된 기억만 다시 꺼내준다.

## 2. 금지하는 복귀 UX

다음 표현과 구조는 사용하지 않는다.

- `30일 만에 돌아오셨네요`
- `3개월 동안 기록하지 않았어요`
- `검토하지 않은 원칙이 18개 있어요`
- `밀린 회고를 완료하세요`
- 연속 사용 일수 또는 스트릭 복구
- 미사용 기간을 실패, 공백, 누락으로 표현
- 사용하지 않은 기간의 기록을 소급 작성하도록 요구
- 오래된 Review 후보를 한꺼번에 backlog처럼 제시

미사용 기간은 제품 관점에서 결손 데이터가 아니다.

## 3. 복귀 시 기본 동작

장기간 미사용 후 앱을 열어도 기본적으로 기존 홈을 사용할 수 있어야 한다.

앱은 별도의 강제 복귀 마법사나 설문을 띄우지 않는다.

사용자에게 도움이 될 만한 이전 맥락이 있고 재노출 정책상 안전한 경우에만 작은 `이전 맥락 다시 보기` 진입점을 제공할 수 있다.

복귀 카드의 목적은 처리할 일을 만드는 것이 아니라 기억을 복구하는 것이다.

## 4. 복귀 Snapshot

사용자가 `이전 맥락 다시 보기`를 선택하면 최대 소수의 정보만 보여준다.

후보 우선순위:

1. 사용자가 마지막으로 직접 선택했던 `activeAnchor`
2. 사용자가 명시적으로 다시 봐도 된다고 설정한 retained/reviewable MeaningNode
3. 마지막 MeaningCheckIn에서 사용자가 중요하다고 재확인한 항목
4. 사용자가 직접 지정한 재검토 시점이 지난 항목

다음은 기본 후보가 아니다.

- 임의의 CaptureEntry
- 임의의 ReflectionItem
- 임의의 SynthesisInsight
- 단순히 오래되었다는 이유만으로 선택된 개인 기록
- 종료되었거나 resurfacing 제외 상태인 항목

## 5. 복귀 Snapshot 문구

복귀 경험은 사용하지 않은 기간보다 과거 맥락에 초점을 둔다.

권장 의미:

- `마지막으로 중요하게 두었던 문장`
- `이전에 계속 기억하고 싶다고 남겨둔 것`
- `이 생각을 왜 중요하게 여겼는지 다시 보기`

피해야 할 의미:

- `오랜만이에요`
- `다시 시작해볼까요?`
- `이번에는 꾸준히 해봐요`
- `밀린 것부터 정리해볼까요?`

## 6. 재노출 Eligibility

일반 개인 기록은 기본적으로 자동 resurfacing 대상이 아니다.

자동 Review 또는 복귀 Snapshot 후보가 되려면 사용자가 해당 MeaningNode를 명시적으로 재노출 가능한 항목으로 남겼거나 제품 흐름상 그 의사가 명확해야 한다.

예:

- 잠금화면 후보로 승인한 Commitment
- `계속 기억하고 싶음`으로 표시한 원칙
- `나중에 다시 확인`을 직접 선택한 항목
- 사용자가 날짜를 지정해 재검토하기로 한 항목

단순히 데이터베이스에 존재한다는 이유만으로 다시 보여주지 않는다.

## 7. 다시 보여주지 않기

사용자는 항목 단위로 다음을 선택할 수 있어야 한다.

- 당분간 다시 보여주지 않기
- 자동 재노출에서 제외
- 직접 찾을 때만 보기

이 선택은 삭제가 아니다.

검색, 직접 탐색, Why Trail에서 사용자가 의도적으로 접근하는 것은 계속 허용한다.

## 8. 기간과 태그 단위 제외

장기적으로는 사용자가 특정 범주의 자동 재노출을 막을 수 있어야 한다.

지원 후보:

- 특정 기간의 기록 자동 재노출 제외
- 특정 태그 자동 재노출 제외
- 특정 회고 세션 자동 재노출 제외

예를 들어 사용자가 특정 관계나 과거 사건에 대한 기록은 보존하고 싶지만 예상하지 못한 순간에는 보고 싶지 않을 수 있다.

이 경우 보존과 재노출을 분리한다.

## 9. 재노출 이유 설명

Review 또는 복귀 Snapshot으로 어떤 항목을 보여줄 때에는 왜 지금 선택되었는지를 사용자가 이해할 수 있어야 한다.

예시:

- `예전에 계속 기억하고 싶다고 남겨둔 원칙입니다.`
- `직접 오늘 다시 보기로 설정한 항목입니다.`
- `마지막으로 대표 문장으로 사용했던 내용입니다.`

알고리즘이 설명 가능한 이유를 만들 수 없으면 자동으로 노출하지 않는다.

## 10. 민감한 과거와 Surprise Recall 금지

`On This Day`처럼 날짜가 같다는 이유만으로 과거 기록을 자동 노출하는 기능은 기본 제품에 넣지 않는다.

다음 자료는 사용자의 명시적 선택 없이 surprise recall 대상으로 사용하지 않는다.

- 관계 관련 개인 기록
- 상실, 실패, 수치심 등 강한 감정을 포함할 가능성이 있는 원문
- retired 항목의 원문
- 일반 빠른 기록
- 과거 회고 원문

사용자가 검색하거나 시간 여행 기능으로 직접 찾아보는 것과 앱이 예상하지 못한 시점에 보여주는 것은 다른 행동으로 취급한다.

## 11. 복귀 이후 행동 요구 금지

복귀 Snapshot을 본 뒤 앱은 다음 행동을 요구하지 않는다.

- 목표 다시 설정
- 새로운 Practice 만들기
- 오늘 할 행동 정하기
- 밀린 Review 처리
- Synthesis 만들기

사용자는 내용을 읽고 앱을 닫아도 해당 복귀 세션이 완결된 것으로 본다.

원하는 경우에만 다음 선택지를 열 수 있다.

- 왜 중요했는지 보기
- 지금의 생각 남기기
- 아직 중요한지 다시 확인하기
- 더 이상 자동으로 보여주지 않기

## 12. 로컬 미사용 정보

복귀 UX를 위해 마지막 사용 시각 등의 로컬 메타데이터를 저장할 수 있다.

이 정보는 다음 용도로만 사용한다.

- 복귀용 UI를 과도하게 반복하지 않기
- 이전 맥락 복구 진입점 제공 여부 판단

미사용 일수 점수화, 스트릭, 사용자 평가, 외부 분석 전송에 사용하지 않는다.

## 13. 성공 기준

복귀 경험은 다음을 만족해야 한다.

- 사용자가 오래 앱을 사용하지 않아도 죄책감이나 실패감을 유도하지 않는다.
- 복귀 직후 처리해야 할 backlog를 만들지 않는다.
- 이전에 중요했던 맥락을 원하면 빠르게 복구할 수 있다.
- 민감한 일반 기록을 예상하지 못한 순간에 자동 노출하지 않는다.
- 사용자가 `다시 보여주지 않기`를 선택할 수 있다.
- 재노출 시 왜 지금 이 항목이 보이는지 이해할 수 있다.
- 아무것도 검토하거나 행동하지 않고 앱을 닫아도 정상적인 사용으로 간주한다.
