# Future Self 화면 상태와 예외 UX

- 상태: UX 구현 기준
- 작성일: 2026-09-05
- 상위 기준: `docs/PRD.md`
- 관련 문서: `docs/INFORMATION_ARCHITECTURE.md`, `docs/USER_FLOWS.md`

이 문서는 주요 화면의 empty, loading, error, privacy, lifecycle 상태를 정의한다.

## 1. 공통 상태 원칙

1. 데이터가 없는 상태를 결핍이나 실패로 표현하지 않는다.
2. 미분류, 미연결, 미검토는 오류가 아니다.
3. private 화면은 인증 전 잠깐이라도 렌더링하지 않는다.
4. destructive action은 범위와 결과를 명확히 보여준다.
5. 로딩 실패가 데이터 없음처럼 보이면 안 된다.
6. Widget, backup, export처럼 외부 시스템이 개입하는 기능은 완료 보장을 과장하지 않는다.
7. 사용자에게 `해야 할 일`을 새로 만들어내는 empty state 문구를 피한다.

## 2. 홈 상태

### H-01-A 완전 초기 상태

표시:

- 한 줄 기록 입력
- 짧은 제품 설명
- 선택적 잠금화면 문장 만들기 진입

표시하지 않음:

- `아직 기록이 없어요. 첫 기록을 작성하세요` 같은 압박 문구
- 진행률
- 온보딩 체크리스트
- 그래프 설명

### H-01-B activeAnchor 없음

현재 문장 영역은:

- 비워두거나
- `잠금화면에 둘 문장을 직접 선택할 수 있어요` 정도의 선택적 안내

으로 처리한다.

기본 홈 기능 사용에 영향이 없어야 한다.

### H-01-C Review 후보 없음

Review 영역 자체를 숨긴다.

`모든 검토를 완료했습니다` 같은 완료 게임화 문구를 사용하지 않는다.

### H-01-D 이전 맥락 후보 없음

복귀 진입점을 숨긴다.

장기간 미사용 사실을 별도로 알리지 않는다.

### H-01-E 최근 기록 없음

최근 기록 영역을 숨기거나 간단한 설명만 제공한다.

## 3. 빠른 기록 상태

### C-01-A 기본

본문 입력 가능.

### C-01-B 저장 중

중복 저장을 막는다.

UI는 짧은 저장 진행 상태를 표현할 수 있지만 전체 화면 차단은 피한다.

### C-01-C 저장 성공

별도 후속 선택을 강제하지 않고 입력창 초기화 또는 홈 복귀.

### C-01-D 저장 실패

입력한 텍스트를 유지한다.

재시도 가능.

실패한 본문을 로그에 기록하지 않는다.

### C-01-E 앱이 백그라운드로 이동

작성 중 텍스트를 어떻게 보존할지는 구현 단계에서 결정하되, App Switcher에는 private 내용이 보이지 않게 한다.

## 4. 기록 목록 상태

### R-01-A 기록 없음

검색과 회고 진입은 사용할 수 있다.

정리 또는 입력 의무를 만들지 않는다.

### R-01-B 로딩

skeleton 또는 진행 상태를 사용한다.

`기록 없음`을 먼저 보여줬다가 데이터가 나타나는 깜빡임을 피한다.

### R-01-C 로딩 실패

오류와 빈 상태를 구분한다.

재시도 제공.

### R-01-D 대량 데이터

무한 스크롤 또는 페이지 기반 로딩.

전체 revision 또는 전체 그래프를 메모리에 올리지 않는다.

## 5. 검색 상태

### S-01-A 검색어 없음

최근 검색어를 민감 데이터처럼 취급한다.

기본적으로 개인 검색어를 외부 분석에 전송하지 않는다.

### S-01-B 결과 없음

`찾지 못했습니다` 정도로 표시한다.

분류나 새 항목 생성을 강제 제안하지 않는다.

### S-01-C 과거 revision 결과

현재 결과와 명확히 다른 시각 상태를 사용한다.

예:

- `과거 표현`
- revision 날짜

과거 결과를 열어도 현재 데이터를 자동 변경하지 않는다.

### S-01-D 검색 인덱스 재생성 중

검색 기능이 제한될 수 있음을 표시한다.

원본 데이터 손상처럼 표현하지 않는다.

## 6. 회고 상태

### RF-01-A 새 회고

모든 질문이 비어 있어도 저장 또는 종료 가능.

### RF-01-B 일부만 작성

정상 상태.

진행률 퍼센트 없음.

### RF-01-C 질문 미응답

오류 표시 없음.

### RF-01-D 기간 중복

여러 회고 세션의 기간이 겹쳐도 기본적으로 허용한다.

회고는 데이터 정합성보다 사용자의 관점 단위이다.

## 7. Synthesis 상태

### SY-01-A 선택 항목 0개

같이 보기 workspace를 생성하지 않는다.

### SY-01-B 선택 항목 1개

UI상 허용 여부는 구현에서 정할 수 있으나, 여러 기록을 비교하는 목적상 기본 진입은 2개 이상을 권장할 수 있다.

권장은 차단이 아니다.

### SY-01-C Synthesis 본문만 저장

정상 완료.

Meaning Card 또는 행동 노드 연결이 없어도 문제 없음.

### SY-01-D 출처 중 하나가 나중에 삭제됨

hard delete 정책에 따라 삭제된 evidence link를 정리한다.

남은 Synthesis를 유지할 수 있는 경우에는 남은 근거만 보여주고, 삭제된 원문을 ghost 형태로 보존하지 않는다.

## 8. 의미 카드 목록 상태

### M-01-A 카드 없음

`중요한 생각을 카드로 남길 수 있어요` 정도의 선택적 설명.

그래프 만들기를 요구하지 않는다.

### M-01-B 분류되지 않은 카드만 존재

정상 상태.

`정리 필요` 섹션이나 경고 배지를 만들지 않는다.

### M-01-C 카드가 매우 많음

검색, 필터, 정렬을 제공한다.

카드 개수 자체를 성취로 표현하지 않는다.

### M-01-D archived / retired

기본 목록에서는 필요에 따라 숨기고 필터로 볼 수 있게 한다.

종료를 실패 스타일로 표시하지 않는다.

## 9. 의미 카드 상세 상태

### M-02-A 분류 없음

사용 가능한 항목:

- 현재 표현
- 수정
- 출처
- revision history
- generic relation
- 분류 선택
- 종료 / 삭제 / 병합

사용 불가능하거나 의미가 불분명한 typed relation은 숨긴다.

### M-02-B typed

해당 종류에 맞는 관계와 detail을 보여준다.

### M-02-C paused

`일시 중지` 상태를 표시하되 내용과 과거 이력은 읽을 수 있다.

### M-02-D retired

종료 이유와 종료 시점을 보여준다.

재활성화 가능 여부는 lifecycle 규칙을 따른다.

### M-02-E merged

현재 canonical target으로 가는 진입점을 제공한다.

과거 source 기록은 역사 화면에서 확인 가능하다.

## 10. 관계 생성 상태

### REL-01-A 유효한 관계

저장 가능.

### REL-01-B self edge

저장 불가.

간단한 이유를 표시한다.

### REL-01-C typed relation 불일치

스냅되지 않거나 선택 항목에서 제외한다.

사용자에게 내부 타입 규칙을 장황하게 설명하지 않는다.

### REL-01-D causal cycle 위험

저장을 거부한다.

`이 연결은 출처 관계가 서로 순환하게 됩니다`처럼 문제를 설명한다.

semantic relation 자체와 causal provenance 오류를 혼동하지 않는다.

## 11. Focus Board 상태

### FB-01-A 선택 카드 없음

카드 선택 안내.

### FB-01-B 유효한 슬롯 없음

잘못된 상태가 아니라 현재 카드에서 만들 수 있는 관계가 없거나 필터 조건 때문일 수 있다.

### FB-01-C DnD 실패

원위치 복귀 + 텍스트 피드백.

햅틱에만 의존하지 않는다.

### FB-01-D VoiceOver

DnD 대신 `연결 추가` 액션을 제공한다.

## 12. Why Trail 상태

### WT-01-A 출처가 충분함

현재 항목에서 과거로 경로 표시.

### WT-01-B 출처가 하나뿐임

그 하나만 보여준다.

`불완전한 Trail` 경고를 만들지 않는다.

### WT-01-C 출처 없음

`아직 연결된 시작 기록이 없습니다` 정도의 사실만 표시한다.

연결을 요구하지 않는다.

### WT-01-D 과거 relation이 retired됨

현재 관계와 과거 관계를 시점 기준으로 구분한다.

## 13. 갈등 관계 상태

### CF-01-A 갈등만 저장됨

정상 상태.

### CF-01-B Trade-off Reflection 없음

정상 상태.

### CF-01-C 결론 없음

정상 저장 가능.

### CF-01-D 우선순위 기록됨

현재 우선순위는 당시 판단으로 표시한다.

영구 규칙처럼 표현하지 않는다.

## 14. Projection 상태

### P-01-A draft

공개 승인 전.

잠금화면 후보가 될 수 없다.

### P-01-B approved

잠금화면 후보가 될 수 있다.

### P-01-C approved but inactive

정상 상태.

승인됐다고 자동 activeAnchor가 되지 않는다.

### P-01-D active

현재 대표 문장.

### P-01-E revoked

active일 경우 같은 transaction에서 anchor를 해제한다.

### P-01-F Commitment가 수정됐지만 기존 Projection은 그대로

기존 승인 Projection은 자동 변경하지 않는다.

사용자가 새 표현을 만들기 전까지 기존 문장을 유지할 수 있다.

## 15. Widget 상태

### W-01-A Widget 미설치

설치 안내만 제공.

앱이 설치 여부를 완전히 통제한다고 가정하지 않는다.

### W-01-B App Group 갱신 성공, Widget 미반영

`업데이트를 요청했습니다` 수준으로 표현한다.

즉시 반영 보장 문구 금지.

### W-01-C App Group write 실패

Private DB 변경을 rollback하지 않는다.

재동기화 필요 상태를 남긴다.

### W-01-D activeAnchor 없음

Widget은 빈 안전 상태를 표시한다.

임의 다른 문장으로 fallback하지 않는다.

## 16. Review 상태

### RV-01-A 후보 없음

영역 숨김.

### RV-01-B 후보 있음

최대 3개.

각 카드에 resurfacing 이유 표시.

### RV-01-C snoozed

snoozedUntil 전에는 자동 후보에서 제외.

### RV-01-D resurfacing 제외

자동 후보에서 제외.

검색이나 명시적 탐색에서는 사용자가 직접 찾을 수 있다.

## 17. 복귀 상태

### RT-01-A 장기 미사용 후 실행

평소 홈 표시.

### RT-01-B 안전한 복귀 후보 있음

작은 `이전 맥락 다시 보기` 진입점만 제공.

### RT-01-C 안전한 후보 없음

아무 복귀 UI도 추가하지 않는다.

## 18. 시간 여행 상태

### TT-01-A 과거 상태 재구성 성공

선택 날짜와 당시 유효 상태를 표시.

### TT-01-B 해당 시점 데이터 없음

사실만 표시.

### TT-01-C hard delete로 일부 이력 없음

삭제된 내용을 추측하거나 placeholder 원문으로 복원하지 않는다.

### TT-01-D migration 이전의 일부 정보가 표현 불가

가능한 범위와 한계를 명확히 표시한다.

## 19. 앱 잠금 상태

### AL-01-A 잠금 비활성

평소 진입.

### AL-01-B 인증 대기

private UI 미렌더링.

### AL-01-C 인증 실패

계속 잠금 상태.

### AL-01-D 인증 취소

개인 화면을 노출하지 않고 안전 화면 유지.

### AL-01-E background grace period 내 복귀

사용자 설정에 따라 재인증 생략 가능.

## 20. 백업 상태

### BK-01-A 백업 생성 중

진행 상태.

### BK-01-B 성공

저장 위치 또는 공유 결과를 확인할 수 있다.

### BK-01-C 실패

기존 live DB에 영향 없음.

### BK-01-D 백업 오래됨 알림

사용자가 해당 알림을 켠 경우에만 제공.

## 21. 복원 상태

### RS-01-A 복호화 실패

live DB 유지.

### RS-01-B schema migration 실패

live DB 유지.

### RS-01-C 무결성 검증 실패

live DB 유지.

### RS-01-D 검증 성공

원자적 교체 후 앱 재초기화.

### RS-01-E 교체 중 중단

transaction / 파일 교체 전략으로 이전 또는 새 DB 중 하나만 유효하도록 한다.

## 22. export 상태

### EX-01-A 범위 미선택

생성 불가.

### EX-01-B 미리보기

포함되는 데이터 종류와 범위를 표시.

### EX-01-C 앱 잠금 활성 + 재인증 실패

export 중단.

### EX-01-D export 성공

app-private 임시 평문 정리.

### EX-01-E 공유 후 외부 복사본

앱이 삭제할 수 없음을 사전에 안내.

## 23. 삭제 상태

### D-01-A soft lifecycle 종료

retire / archive와 hard delete를 구분한다.

### D-01-B hard delete 확인

복구 불가와 영향 범위 표시.

### D-01-C active Projection 관련 삭제

같은 transaction에서 anchor 안전 해제.

### D-01-D 삭제 성공

검색 인덱스, 캐시 등 파생 데이터에서도 제거.

## 24. 오류 문구 원칙

좋은 오류 문구는:

- 무엇이 실패했는지
- 데이터가 보존됐는지
- 사용자가 할 수 있는 동작이 있는지

를 알려준다.

피해야 할 문구:

- 사용자를 탓하는 표현
- `완료하지 못했습니다`처럼 정상적인 비행동을 실패로 만드는 표현
- 데이터 손실 여부가 불분명한 모호한 오류

## 25. 구현 완료 기준

- empty와 error가 시각적으로 구분된다.
- 미분류와 미연결은 오류 스타일을 사용하지 않는다.
- 인증 전 private content가 렌더링되지 않는다.
- 삭제, merge, restore, projection revoke 같은 복합 변경은 transaction 규칙과 일치한다.
- Widget 갱신을 즉시 완료로 과장하지 않는다.
- Review, 복귀, 회고가 backlog 또는 진행률 UX로 변하지 않는다.
