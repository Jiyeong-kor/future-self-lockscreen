# Future Self 핵심 사용자 흐름

- 상태: UX 구현 기준
- 작성일: 2026-09-05
- 상위 기준: `docs/PRD.md`
- 관련 문서: `docs/INFORMATION_ARCHITECTURE.md`, `docs/SCREEN_STATES.md`

이 문서는 Future Self의 주요 사용자 흐름과 각 흐름의 정상 종료 지점을 정의한다.

핵심 규칙은 다음과 같다.

> 사용자는 기록, 해석, 연결, 행동 결정을 언제든 원하는 지점에서 멈출 수 있으며 그 상태를 실패나 미완료로 취급하지 않는다.

## F-01. 한 줄 기록 후 종료

가장 중요한 기본 흐름이다.

```text
홈
→ 한 줄 입력
→ 저장
→ 홈
```

규칙:

- 본문 외 입력은 필수가 아니다.
- 저장 직후 분류 화면을 자동으로 띄우지 않는다.
- 의미 카드 생성, 목표 연결, 행동 계획, 잠금화면 설정을 요구하지 않는다.
- 저장 완료 자체가 정상적인 최종 상태이다.

## F-02. 기록을 의미 카드로 남기기

사용자가 해당 기록을 단순 메모보다 중요한 생각으로 보존하고 싶을 때만 사용한다.

```text
기록 상세
→ 의미 카드로 남기기
→ 제목 또는 현재 표현 확인
→ 저장
→ 의미 카드 상세
```

기본 생성 상태는 `분류 없음`을 허용한다.

사용자는 여기서 종료할 수 있다.

선택적으로:

- 이유
- 미래상
- 목표
- 실천
- 원칙

중 하나로 분류할 수 있다.

## F-03. 분류되지 않은 의미 카드 유지 또는 나중에 분류

```text
의미 카드 상세
→ 분류 없음 상태 유지
```

이것만으로 정상 상태이다.

나중에 사용자가 원하면:

```text
의미 카드 상세
→ 분류 선택
→ 이유 / 미래상 / 목표 / 실천 / 원칙 중 하나 선택
→ 저장
```

규칙:

- 분류하지 않은 기간을 표시하거나 재촉하지 않는다.
- 미분류 카드 개수를 경고하지 않는다.
- 분류 제안 알림을 보내지 않는다.

## F-04. 의미 카드 연결

탭 기반 흐름:

```text
의미 카드 상세
→ 연결 추가
→ 관계 선택
→ 연결할 카드 검색 또는 선택
→ 미리보기
→ 저장
```

DnD 흐름:

```text
Focus Board
→ 카드 선택
→ Block Tray에서 다른 카드 가져오기
→ 유효한 관계 슬롯에 놓기
→ 저장
```

규칙:

- DnD 없이 동일한 관계를 만들 수 있어야 한다.
- 연결하지 않고 상세 화면으로 돌아가도 아무 상태 변화가 없다.
- 그래프 완성도나 남은 연결 개수를 표시하지 않는다.

## F-05. 여러 기록 같이 보기

```text
기록
→ 선택 모드
→ 여러 기록 선택
→ 같이 보기
→ 선택한 기록 비교
→ 새롭게 발견한 생각 작성
→ SynthesisInsight 저장
```

정상 종료는 여기까지이다.

저장 후 선택적으로:

- 의미 카드로 남기기
- 기존 의미 카드의 출처로 연결

을 할 수 있지만 자동으로 다음 단계로 넘기지 않는다.

## F-06. Synthesis를 아무 행동으로도 연결하지 않기

```text
Synthesis 저장
→ 닫기
```

이 흐름을 제품에서 명시적으로 정상 사용으로 취급한다.

다음 문구를 기본으로 사용하지 않는다.

- 그래서 무엇을 할 건가요?
- 가장 작은 행동은 무엇인가요?
- 최소한 이것만 해보세요
- 목표로 만들어볼까요?

## F-07. Why Trail로 이유 복구

대표 진입:

```text
목표 / 실천 / 원칙 상세
→ 왜 시작했지?
→ Why Trail
```

화면은 현재 항목에서 관련 이유와 과거 기록 쪽으로 거슬러 올라간다.

예시:

```text
현재 원칙
→ 연결된 이유
→ 연결된 미래상
→ 최초 기록
→ 이후 의미 변화
```

사용자는 읽기만 하고 종료할 수 있다.

## F-08. 갈등 관계 만들기

```text
의미 카드 상세
→ 연결 추가
→ 서로 충돌함
→ 다른 카드 선택
→ 저장
```

앱은 해결을 요구하지 않는다.

## F-09. 선택적 갈등 검토

```text
conflicts_with 관계 상세
→ 갈등 다시 보기
→ Trade-off Reflection
```

선택 가능한 입력:

- 둘 다 원하는 이유
- 지금 더 우선하고 싶은 것
- 한쪽을 선택하면 포기하게 되는 것
- 나중에 다시 볼 시점
- 결론 없이 메모만 남기기

모든 입력은 선택 사항이다.

`아직 모르겠다` 또는 아무 결론 없이 저장하는 것도 정상 완료이다.

## F-10. Commitment를 잠금화면 문장으로 만들기

```text
원칙 상세
→ 잠금화면에 두기
→ 공개용 문장 작성
→ 실제 표시 문구 확인
→ 공개 승인
→ 대표 문장으로 설정
```

중요:

- 승인과 대표 설정은 별도 동작이다.
- 승인만 하고 대표 문장으로 설정하지 않을 수 있다.
- 기존 activeAnchor를 자동 교체하지 않는다.

## F-11. 잠금화면 문장 스타일만 바꾸기

```text
현재 문장 상세
→ 문장 꾸미기
→ 배경 / 위치 / 크기 / 정렬 변경
→ 저장
```

텍스트 내용이 동일하면 공개 승인을 다시 요구하지 않는다.

## F-12. 잠금화면 문구 내용 수정

```text
현재 문장 상세
→ 표현 새로 쓰기
→ 새 문구 작성
→ 새 ProjectionRevision 생성
→ 공개 승인
→ 원하면 대표 문장으로 교체
```

새 문구는 이전 승인 상태를 상속하지 않는다.

## F-13. 의미 재확인

사용자가 자발적으로 실행할 때만 가능하다.

```text
의미 카드 또는 현재 문장 관련 원칙 상세
→ 아직 중요함
→ MeaningCheckIn 저장
```

규칙:

- 공개 승인과 무관하다.
- 일정 기간이 지났다고 자동 요구하지 않는다.
- 하지 않아도 기존 잠금화면 문장은 유지될 수 있다.

## F-14. Review 확인

```text
홈 Review 카드
→ 왜 지금 보이는지 확인
→ 상세 열기
```

선택 동작:

- 여전히 중요함
- 지금의 말로 다시 쓰기
- 이유가 달라짐
- 당분간 묻지 않기
- 종료
- 그냥 닫기

`그냥 닫기`도 정상이다.

## F-15. 장기간 미사용 후 복귀

기본:

```text
앱 실행
→ 평소 홈
```

안전한 이전 맥락이 있는 경우에만:

```text
홈
→ 이전 맥락 다시 보기
→ 과거 activeAnchor 또는 재노출 가능한 의미 확인
→ 닫기
```

금지:

- 미사용 기간 강조
- 밀린 회고 수 표시
- Review backlog
- 다시 시작하기 마법사 강제

## F-16. 검색으로 과거 기록 찾기

```text
기록
→ 검색
→ 검색어 입력
→ 결과 선택
→ 상세
```

선택적으로:

```text
검색 필터
→ 과거 표현까지 검색 켜기
→ historical revision 결과 확인
```

현재 표현과 과거 표현을 명확히 구분한다.

## F-17. 현재와 과거 표현 비교

```text
의미 카드 또는 기록 상세
→ 변경 이력
→ 과거 revision 선택
→ 현재와 비교
```

사용자가 원할 때만 연다.

## F-18. 특정 시점의 의미 보기

```text
시간 여행
→ 날짜 선택
→ 당시 유효한 표현과 관계 재구성
```

현재 상태를 덮어쓰지 않는다.

## F-19. 의미 카드 수정

```text
의미 카드 상세
→ 수정
→ 저장
→ 새 revision 생성
```

기존 revision은 유지한다.

## F-20. 의미 카드 종료

```text
의미 카드 상세
→ 종료
→ 종료 이유 선택 또는 메모
→ 저장
```

종료는 삭제가 아니다.

종료한 이유와 당시 표현을 이후 확인할 수 있다.

## F-21. 중복 의미 카드 병합

```text
의미 카드 상세
→ 중복 카드와 병합
→ source / target 확인
→ 병합 결과 미리보기
→ 저장
```

규칙:

- 과거 관계 endpoint를 소급 변경하지 않는다.
- 현재 탐색에서 canonical target으로 resolve한다.
- 병합은 동일하거나 사실상 같은 의미일 때만 사용한다.

## F-22. 완전 삭제

```text
상세
→ 삭제
→ 삭제 범위 및 복구 불가 안내
→ 확인
→ hard delete transaction
```

사용자의 삭제 요청은 역사 보존보다 우선한다.

## F-23. 회고 작성

```text
기록
→ 회고
→ 새 회고
→ 기간 선택
→ 원하는 질문만 작성
→ 저장
```

규칙:

- 질문별 진행률을 표시하지 않는다.
- 모든 질문에 답할 필요가 없다.
- 한 항목만 작성하고 종료할 수 있다.

## F-24. 앱 잠금

설정:

```text
설정
→ 앱 잠금
→ 시스템 인증
→ 정책 선택
→ 저장
```

잠금 상태 진입:

```text
앱 실행
→ private UI를 렌더링하지 않은 잠금 상태
→ 시스템 인증
→ 성공 후 화면 표시
```

인증 취소 시 개인 화면이 잠깐 보이면 안 된다.

## F-25. 백업

```text
설정
→ 백업
→ 암호화 백업 생성
→ 저장 위치 선택
```

백업은 machine recovery 용도이다.

## F-26. 복원

```text
설정
→ 복원
→ 백업 선택
→ 임시 저장소에서 복호화
→ migration
→ 무결성 검증
→ 성공 시 live DB 원자 교체
```

검증 실패 시 기존 DB를 유지한다.

## F-27. 사람이 읽을 수 있는 내보내기

```text
설정 또는 대상 상세
→ 내보내기
→ 범위 선택
→ 내보낼 내용 미리보기
→ 필요 시 재인증
→ Markdown 생성
→ 공유 또는 저장
```

내보내기는 백업과 다르다.

## F-28. App Intent / Shortcut 빠른 기록

후속 구현:

```text
Shortcuts / Action Button / Siri 진입
→ Future Self 빠른 기록 열기
→ 필요 시 인증
→ 입력
→ 저장
```

민감 원문이 OS 표면에 남을 수 있는 방식은 기본으로 사용하지 않는다.

## 29. 플로우 설계 불변조건

- 저장 후 자동으로 다음 의미 작업을 강제하지 않는다.
- 행동 계획을 요구하는 화면은 기본 플로우에 넣지 않는다.
- 미분류와 미연결은 오류가 아니다.
- Review와 복귀는 backlog를 만들지 않는다.
- 갈등은 해결하지 않아도 된다.
- 공개 승인, activeAnchor 설정, 의미 재확인은 서로 별도 동작이다.
- 삭제를 제외한 수정은 과거 이력을 덮어쓰지 않는다.
