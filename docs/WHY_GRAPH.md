# Why Graph 도메인 설계

- 문서 상태: Draft v0.1
- 작성일: 2026-09-03
- 대상 PRD: `docs/PRD.md` v0.3 이후

## 1. 목적

Future Self Lockscreen은 단순히 하나의 후회에서 하나의 행동 원칙을 만드는 앱으로 제한하지 않는다.

사용자가 실제로 행동하는 이유는 서로 얽혀 있을 수 있다.

예를 들어 사용자는 다음과 같이 생각할 수 있다.

- 미래에 좋은 파트너를 만나고 싶다.
- 그래서 자기관리를 잘하는 사람이 되고 싶다.
- 자기관리에는 체중 관리뿐 아니라 피부 관리, 생활 관리, 경제적 준비도 포함된다.
- 돈을 모으는 이유에는 미래의 관계를 준비한다는 의미도 있지만 또래보다 뒤처지고 싶지 않다는 별도의 동기도 있을 수 있다.

즉, 하나의 행동은 여러 이유를 가질 수 있고 하나의 이유는 여러 목표와 행동으로 이어질 수 있다.

또한 시간이 지나면 사용자는 기존의 이유를 더 이상 중요하게 생각하지 않을 수 있다. 반대로 잠시 의미를 잃었다가 다시 초심을 찾을 수도 있다.

따라서 제품은 `후회 → 원칙`의 단일 연결이 아니라 **동기, 미래상, 목표, 실천, 변화 원칙, 회고가 서로 다대다로 연결되는 의미 그래프 Why Graph**를 내부 도메인으로 사용한다.

## 2. 핵심 원칙

### 2.1 하나의 행동에는 여러 이유가 있을 수 있다

`돈 모으기`라는 목표는 다음과 같은 여러 동기에 동시에 연결될 수 있다.

- 미래의 가족 생활을 안정적으로 준비하고 싶다.
- 또래보다 경제적으로 뒤처지고 싶지 않다.
- 경제적 선택권을 갖고 싶다.

앱은 하나의 대표 이유만 강제로 선택하게 하지 않는다.

### 2.2 하나의 이유는 여러 행동으로 이어질 수 있다

`내가 원하는 관계를 준비할 수 있는 사람이 되고 싶다`는 미래상은 다음과 연결될 수 있다.

- 건강 관리
- 피부 관리
- 생활 기술 익히기
- 재정 관리
- 의사소통 능력 개선

### 2.3 이유는 변할 수 있다

사용자가 과거에 중요하게 생각했던 동기는 현재 더 이상 중요하지 않을 수 있다.

제품은 과거의 이유를 삭제해서 현재 가치관에 맞게 역사를 다시 쓰지 않는다.

대신 다음 정보를 구분한다.

- 당시에는 왜 중요했는가
- 지금도 그 이유가 유효한가
- 이유가 달라졌다면 무엇으로 달라졌는가
- 사용자가 그 변화를 언제 인식했는가

### 2.4 초심은 원문과 시점을 보존한다

사용자가 처음 결심했을 때 작성한 문장과 당시 맥락은 이후 편집으로 덮어쓰지 않는다.

현재 표현은 수정할 수 있지만 최초 기록은 `OriginMoment`로 별도 보존한다.

### 2.5 초심을 다시 찾은 순간도 새로운 기록이다

사용자가 어느 날 `내가 이걸 왜 하고 있었지?`라고 느꼈다가 다시 의미를 찾았다면 그 순간은 원래 초심과 다른 중요한 기록이다.

제품은 이를 `MeaningCheckIn`으로 저장한다.

따라서 사용자는 나중에 다음과 같은 시간 흐름을 볼 수 있다.

`처음 시작한 이유 → 중간에 의미가 흐려진 시점 → 다시 의미를 찾은 시점 → 이유를 수정한 시점`

## 3. 사용자에게 보이는 개념

내부 데이터는 그래프형이지만 사용자가 처음부터 그래프 편집기를 배워야 해서는 안 된다.

사용자에게는 다음 질문과 동작으로 표현한다.

### 3.1 왜 하고 있나요?

목표 또는 실천을 만들 때 하나 이상의 이유를 연결한다.

예시:

`돈 모으기`

- 미래의 가정을 안정적으로 준비하고 싶어서
- 경제적으로 뒤처지고 싶지 않아서

### 3.2 이것과 연결된 다른 것은 무엇인가요?

기존에 만든 목표, 원칙 또는 미래상에 연결할 수 있다.

예시:

`좋은 관계를 준비할 수 있는 사람이 되기`

연결된 항목:

- 체중 관리
- 피부 관리
- 생활 기술 익히기
- 돈 모으기

### 3.3 내가 이걸 왜 시작했지?

모든 목표, 실천, 변화 원칙 상세 화면에는 `왜 시작했지?` 진입점을 제공한다.

앱은 현재 항목에서 상위 이유를 따라가며 다음을 보여준다.

1. 현재 하고 있는 것
2. 이것을 시작한 이유
3. 그 이유가 연결된 더 큰 미래상 또는 가치
4. 최초 회고나 결심이 있다면 당시 원문
5. 이후 의미를 다시 확인했던 기록

이 화면의 내부 이름은 `Why Trail`로 정의한다.

### 3.4 이 이유는 아직 중요한가요?

사용자는 동기나 목표를 다시 평가할 수 있다.

선택 예시:

- 여전히 중요하다
- 중요하지만 이유가 달라졌다
- 더 이상 중요하지 않다
- 지금은 잘 모르겠다

`더 이상 중요하지 않다`를 선택해도 과거 기록은 삭제하지 않는다. 현재 그래프에서 비활성화하고 변경 시점을 남긴다.

## 4. Why Graph 노드

### 4.1 `ReflectionItem`

과거 경험, 후회, 아쉬움, 깨달음을 기록한다.

예시:

- 12월마다 수능을 봤어야 했다고 생각했다.
- 올해 돈을 거의 모으지 못한 것이 아쉽다.

### 4.2 `Motive`

사용자가 어떤 목표나 행동을 중요하게 생각하는 이유이다.

예시:

- 선택권이 많은 삶을 살고 싶다.
- 또래보다 경제적으로 뒤처지고 싶지 않다.
- 미래의 관계를 위해 나 자신을 잘 관리하고 싶다.

Motive는 제품이 좋거나 나쁜 이유라고 평가하지 않는다. 사용자가 나중에 스스로 재평가할 수 있도록 기록한다.

### 4.3 `Vision`

사용자가 되고 싶은 사람이나 원하는 미래 상태이다.

예시:

- 자기관리를 꾸준히 하는 사람
- 좋은 관계를 만들어갈 준비가 된 사람
- 경제적으로 선택권이 있는 사람

`Motive`가 왜 중요한지를 설명한다면 `Vision`은 어떤 상태를 원하는지를 설명한다.

### 4.4 `Goal`

도달하고 싶은 결과이다.

예시:

- 올해 일정 금액을 모은다.
- 피부 상태를 꾸준히 관리한다.
- 건강한 체중 범위를 유지한다.

### 4.5 `Practice`

반복해서 실행할 구체적인 행동이다.

예시:

- 월급을 받으면 일정 금액을 먼저 저축한다.
- 저녁 스킨케어를 한다.
- 일주일에 정해진 횟수만큼 운동한다.

### 4.6 `Commitment`

회고나 의미 탐색을 통해 만든 행동 원칙이다.

예시:

- 중요한 미래를 위해 필요한 준비를 당장의 귀찮음 때문에 미루지 않는다.

잠금화면에 지속 노출되는 기본 대상은 `Commitment`이다.

## 5. 관계 모델

노드는 다대다로 연결할 수 있다.

### 5.1 기본 관계 타입

| 관계 | 방향 | 의미 |
| --- | --- | --- |
| `motivated_by` | Goal, Practice, Commitment → Motive | 이 행동이나 목표를 하는 이유 |
| `contributes_to` | Practice, Commitment → Goal | 이 실천이 어떤 목표에 기여하는지 |
| `serves` | Goal, Motive → Vision | 이 목표나 동기가 어떤 미래상을 향하는지 |
| `derived_from` | Motive, Goal, Commitment → ReflectionItem | 어떤 회고나 경험에서 생겼는지 |
| `supports` | 노드 → 노드 | 직접적인 상하 구조는 아니지만 서로 강화하는 관계 |
| `conflicts_with` | 노드 ↔ 노드 | 두 이유나 목표가 현재 서로 충돌한다고 사용자가 판단한 관계 |
| `supersedes` | 새 노드 → 이전 노드 | 과거의 이유나 원칙을 새 관점이 대체한 관계 |

### 5.2 관계도 시간에 따라 변한다

관계를 물리적으로 삭제하는 대신 활성 상태와 기간을 기록한다.

예를 들어 처음에는 `돈 모으기 → 또래보다 뒤처지고 싶지 않음`이 중요한 연결이었지만, 시간이 지나 `경제적 선택권을 갖고 싶음`이 더 중요한 이유가 될 수 있다.

이 경우 과거 관계를 지우지 않고 기존 관계를 종료한 뒤 새 관계를 추가한다.

## 6. 예시 그래프

```text
[Vision] 좋은 관계를 만들어갈 준비가 된 사람이 되고 싶다
    ↑ serves
[Motive] 나 자신을 잘 관리하고 싶다
    ↑ motivated_by                ↑ motivated_by
[Goal] 건강 관리              [Goal] 생활 역량 키우기
    ↑ contributes_to              ↑ contributes_to
[Practice] 운동                 [Practice] 생활 기술 익히기
[Practice] 피부 관리

[Goal] 돈 모으기
    ├─ motivated_by → [Motive] 미래 생활을 안정적으로 준비하고 싶다
    └─ motivated_by → [Motive] 또래보다 경제적으로 뒤처지고 싶지 않다

[Goal] 돈 모으기
    └─ serves → [Vision] 경제적으로 선택권이 있는 사람이 되고 싶다
```

이 구조에서는 `돈 모으기`가 어느 하나의 이유에 종속되지 않는다.

사용자가 `왜 돈을 모으려고 했지?`를 누르면 연결된 여러 이유와 그 이유가 만들어진 시점을 확인할 수 있다.

## 7. 초심과 의미 변화 기록

### 7.1 `OriginMoment`

목표, 동기, 미래상 또는 변화 원칙을 처음 만든 시점의 스냅샷이다.

보존 항목:

- 당시 작성한 원문
- 기록 시각
- 어떤 회고에서 나왔는지
- 당시 사용자가 남긴 맥락
- 최초에 연결되어 있던 이유와 관계

최초 기록은 이후 편집으로 덮어쓰지 않는다.

### 7.2 `MeaningCheckIn`

사용자가 의미를 다시 검토한 사건이다.

종류:

- `reaffirmed`: 초심을 다시 확인함
- `reframed`: 이유를 새롭게 해석함
- `weakened`: 중요성이 줄었다고 느낌
- `retired`: 더 이상 현재의 이유가 아니라고 결정함
- `uncertain`: 아직 판단하지 못함

기록 질문 예시:

- 무엇 때문에 이 목표가 갑자기 의미 없어 보였나요?
- 처음에는 왜 시작했나요?
- 지금 다시 생각했을 때 여전히 중요한 부분은 무엇인가요?
- 지금의 나는 어떤 이유로 계속하고 싶나요?
- 오늘 다시 붙잡고 싶은 한 문장은 무엇인가요?

### 7.3 초심을 다시 찾은 마음

사용자가 `reaffirmed` 또는 `reframed`를 선택하면 그 순간의 문장을 별도 보존한다.

예시:

- 처음 마음: `내년 12월에는 다시 후회하고 싶지 않다.`
- 몇 달 뒤 의문: `이렇게까지 공부하는 게 정말 의미가 있나?`
- 다시 찾은 의미: `내가 원하는 건 시험 자체가 아니라 내가 원하는 전공을 다시 선택할 기회를 만드는 것이다.`

이 세 문장을 하나로 합쳐 덮어쓰지 않는다.

앱은 시간순으로 보여준다.

## 8. Why Trail

`Why Trail`은 그래프를 사용자가 이해하기 쉬운 이야기 형태로 펼치는 화면이다.

예시:

```text
지금 하는 것
돈 모으기

왜?
경제적으로 선택권이 있는 사람이 되고 싶어서
또래보다 뒤처지고 싶지 않아서

이 생각은 어디서 시작됐나요?
2026년 회고
"올해 저축을 거의 하지 못한 것이 아쉬웠다."

의미를 다시 확인한 기록
2027-05-14
"비교 때문에만 돈을 모으는 것은 지쳤다. 하지만 선택권을 갖고 싶다는 이유는 여전히 중요하다."
```

그래프의 모든 경로를 한 번에 보여주지 않는다.

사용자가 한 단계씩 더 깊게 들어갈 수 있도록 한다.

## 9. 잠금화면과 Why Graph의 관계

잠금화면에는 복잡한 그래프를 그대로 노출하지 않는다.

잠금화면의 역할은 현재 가장 중요한 `Commitment` 한 문장을 반복적으로 보여주는 것이다.

앱 내부에서는 해당 문장을 눌렀을 때 다음 내용을 확인할 수 있다.

- 이 원칙이 연결된 목표
- 이 목표를 원하는 이유
- 연결된 미래상
- 원래 회고
- 초심 기록
- 의미를 다시 확인한 기록

따라서 잠금화면은 그래프의 최종 출력 지점이고 앱 내부의 `Why Trail`은 그 문장의 의미를 복구하는 지점이다.

  validTo?: string;

export type OriginMoment = {

  | 'reaffirmed'

### 10.1 그래프형 도메인과 저장소 선택

도메인이 그래프형이라고 해서 그래프 데이터베이스를 도입할 필요는 없다.

MVP는 한 기기에서 동작하고 데이터 규모가 작으므로 로컬 관계형 저장소로 충분하다.

권장 저장 구조:

- 노드 테이블
- 관계 테이블
- 회고 테이블
- OriginMoment 테이블
- MeaningCheckIn 테이블

관계 테이블의 `fromNodeId`, `toNodeId`를 통해 다대다 연결을 표현한다.

단순 Key-Value 저장은 관계 조회, 관계 변경 이력, 마이그레이션이 복잡해질 수 있으므로 이 요구사항이 확정된 시점부터는 SQLite 계열의 관계형 로컬 저장 구조를 기본 방향으로 둔다.

구체적인 React Native 라이브러리는 구현 시작 시 유지보수 상태를 확인한 뒤 선택한다.

## 11. 데이터 불변 조건

### 11.1 원본 기록 불변

`OriginMoment.originalText`는 생성 후 수정하지 않는다.

사용자가 현재 표현을 바꾸고 싶다면 MeaningNode를 수정하거나 새 CheckIn을 추가한다.

### 11.2 이력 삭제와 현재 상태 변경을 구분한다

사용자가 `이 이유는 이제 중요하지 않다`고 판단한 경우 기본 동작은 기록 삭제가 아니다.

- 노드 또는 관계를 `retired` 또는 비활성 상태로 변경한다.
- 변경 시각을 남긴다.
- 현재 선택 알고리즘에서는 제외한다.
- 과거 Why Trail에서는 계속 조회할 수 있다.

사용자가 명시적으로 완전 삭제를 요청할 때만 실제 데이터를 삭제한다.

### 11.3 순환 관계 허용 범위를 제한한다

`supports`와 `conflicts_with`를 제외한 목적 관계는 의미 없는 순환이 생기지 않도록 검증한다.

예를 들어 `Goal A contributes_to Goal B`와 동시에 `Goal B contributes_to Goal A`인 구조는 사용자가 명시적으로 다른 의미를 적지 않는 한 막는다.

## 12. P0, P1 범위

### P0 데이터 모델

처음 구현부터 다음 구조는 지원해야 한다.

- 하나의 변화 원칙에 여러 Motive 연결
- 하나의 Motive에 여러 Goal 또는 Commitment 연결
- Goal과 Practice 연결
- OriginMoment 보존
- MeaningCheckIn 기록
- 관계 비활성화와 이력 보존
- `왜 시작했지?` Why Trail

그래프 구조를 나중에 추가하면 기존 단일 `reflectionItemId` 중심 모델을 크게 마이그레이션해야 하므로 데이터 구조는 P0부터 다대다를 지원한다.

### P0 UI

그래프 시각화는 필수가 아니다.

사용자에게는 다음 UI만 제공해도 된다.

- `이걸 왜 하고 있나요?` 이유 여러 개 연결
- `이것과 연결` 기존 항목 선택
- `왜 시작했지?` Why Trail
- `의미 다시 확인하기` Meaning Check-In
- 시간순 의미 기록

### P1 UI

- 전체 Why Graph 시각화
- 목표별 연결 지도
- 한 Motive가 영향을 주는 여러 행동 보기
- 서로 충돌하는 목표 또는 이유 표시
- 연결이 없는 고립된 목표 확인
- 정기적인 의미 재검토

### P2

- 사용자가 요청할 때만 AI가 기존 기록에서 연결 후보를 제안
- 의미 변화 요약
- 장기간의 가치관 변화 비교

AI는 새로운 동기나 가치관을 사용자 대신 만들어내지 않고 기존 기록을 연결하거나 요약하는 보조 기능으로 제한한다.

## 13. 제품 관점에서의 효과

이 구조를 사용하면 Future Self Lockscreen은 단순한 연말 회고 앱보다 더 긴 시간축을 다룰 수 있다.

사용자는 새로운 정보를 계속 추가하면서 자신의 행동이 무엇과 연결되어 있는지 축적할 수 있다.

또한 시간이 지나 특정 행동이 의미 없다고 느껴졌을 때 제품은 `그냥 계속해라`라고 압박하지 않는다.

대신 다음을 보여준다.

- 처음에는 왜 시작했는가
- 당시 어떤 삶을 원했는가
- 지금도 그 이유가 유효한가
- 이유가 달라졌다면 무엇이 달라졌는가
- 다시 의미를 찾았다면 그 순간 무엇을 느꼈는가

따라서 이 제품이 보존하는 것은 목표 목록만이 아니라 **사용자가 자신의 선택에 부여했던 의미의 역사**이다.
